# 敵方 AI

**驗證對象**：電腦控制單位在地圖上的決策與行動，以本檔為唯一正典。涵蓋 `FDPS.LE` 的 `fdps_map_actor_behavior_step`（`0x10010`）、`fdps_collect_targets_in_area`（`0x109f0`）、`fdps_collect_targets_in_range`（`0x11e50`）、`fdps_map_actor_score_best_attack`（`0x12230`）、`fdps_check_can_counter_attack_from_tile`（`0x125c0`）、`fdps_map_actor_move_toward_nearest_reachable_opponent`（`0x126b0`）、`fdps_map_actor_move_toward_nearest_opponent`（`0x127c0`）、`fdps_map_actor_take_best_action`（`0x12c10`）、`fdps_map_actor_move_and_attack`（`0x12e50`）、`fdps_map_actor_score_best_item`（`0x13040`）、`fdps_score_targets_for_item`（`0x132b0`）、`fdps_map_actor_score_best_spell`（`0x13420`）、`fdps_collect_targets_in_line`（`0x13670`）、`fdps_check_can_counter_attack`（`0x137e0`）、`fdps_score_targets_for_spell`（`0x13920`）、`fdps_score_targets_without_status`（`0x13c20`）、`fdps_map_actor_cast_chosen_spell`（`0x13c90`）、`fdps_map_find_chest_cell`（`0x13e10`）與 `fdps_map_actor_use_item`（`0x27180`）。C 原始碼在 `src/mapai.c`、`src/aiscore.c`、`src/aitarget.c`、`src/aiact.c`。

單位記錄的欄位佈局見 [`data_structures.md`](data_structures.md)，`ITEM.DAT`／`MAGICDAT.DAT` 的欄位與各筆數值見 [`../assets/items.md`](../assets/items.md) 與 [`../assets/spells.md`](../assets/spells.md)，部署記錄裡 AI 行為 byte 的來源與出貨統計見 [`../resource_info/map.md`](../resource_info/map.md)，移動範圍的擴散、路徑與 `fdps_battle_move_unit_toward` 怎麼選落腳格見 [`movement.md`](movement.md)，回合流程與休息見 [`battle.md`](battle.md)。本檔用到的單位記錄欄位：`+0`／`+1` 所在格、`+5` 狀態旗標（bit 0 退場、bit 7 本回合已行動）、`+6` 陣營（0 敵方、1 友軍 NPC、2 我方）、`+7` 肖像編號、`+8` 角色編號、`+0x20` 職業、`+0x22`–`+0x27` 六個狀態計時器、`+0x34` AI 行為 byte、`+0x35`／`+0x36` 目的地、`+0x3b` 移動力、`+0x3d` 事件碼、`+0x40` 現有 HP、`+0x42` HP 上限、`+0x44` 現有 MP、`+0x48` 攻擊力、`+0x4a` 防禦力。

## 誰在什麼時候跑 AI

一個電腦單位的一整個回合就是一次 `fdps_map_actor_behavior_step`（`0x10010`）。它有四個呼叫端：

| 呼叫端 | 對誰 | `side_select` |
| --- | --- | --- |
| `fdps_battle_enemy_turn_phase`（`0x12960`） | 陣營 0、未退場、本回合未行動、麻痺計時器（`+0x26`）為 0 的單位 | 0 |
| `fdps_battle_npc_turn_phase`（`0x12b20`） | 條件同上，陣營 1 | 1 |
| `fdps_title_demo`（`0x2ac10`） | 標題畫面示範戰的每個未退場單位 | 該單位自己的陣營 byte：我方 12 格在示範開始時被改成陣營 1，所以是 1；`MAP25` 部署的敵人是 0 |
| `fdps_icon_script_run`（`0x21650`） | 過場腳本指定的單位 | 腳本給的值 |

敵方階段對單位陣列掃**兩遍**：第一遍先替每個合格的敵人跑法術評分與道具評分，兩者任一達 6 才讓它行動；第二遍讓第一遍沒動的合格敵人全部行動。所以有東西值得施放或使用的敵人一律先於只會走過去砍的敵人行動。NPC 階段只掃一遍、沒有評分門檻，照單位索引順序行動。兩個階段每處理完一個單位都會觸發待辦的格子事件與章節的行動後處理，戰鬥結束碼一旦非 0 就立刻結束該階段；這部分屬於回合流程，見 [`battle.md`](battle.md)。

## `side_select` 與目標陣營

`side_select` 是**真假值，不是陣營編號**：0 代表「敵方的眼光」，非 0 代表「友軍的眼光」。整套 AI 從來不拿它去和陣營 byte 比大小，而是各處自己換算成「要收哪一側的單位」：

| 用途 | `side_select` = 0 | `side_select` ≠ 0 |
| --- | --- | --- |
| 物理攻擊的對象（`fdps_map_actor_score_best_attack`（`0x12230`）） | 陣營 ≠ 0（我方與 NPC） | 陣營 = 0 |
| 直線最近的對手（`fdps_map_actor_move_toward_nearest_opponent`（`0x127c0`）） | 陣營 ≠ 0 | 陣營 = 0 |
| 路徑最近的對手（`fdps_map_actor_move_toward_nearest_reachable_opponent`（`0x126b0`）） | 陣營 ≠ 0（不看 `side_select`，寫死） | 陣營 ≠ 0（同左） |
| 法術、道具的收集模式 | `記錄的對象 byte == 0` 的真假值（0 或 1） | 記錄的對象 byte 原值 |

法術（`MAGICDAT.DAT` `+0x06`）與道具（`ITEM.DAT` `+0x11`）的對象 byte 在敵方眼光下是**布林反轉**：原值 0 變成模式 1，其餘任何值（1、3、5⋯）一律變成模式 0。模式怎麼對到陣營見下面「目標收集」。

## 行為代碼

`fdps_map_actor_behavior_step`（`0x10010`）先查單位是否已退場（旗標 bit 0），已退場就什麼都不做直接返回。接著只取 AI 行為 byte 的**低 4 bit** 分派（`AND AL,0xf`），高 4 bit 不參與分派。目的地 `+0x35`／`+0x36` 與事件碼 `+0x3d` 在分派前讀一次存起來，之後的比較一律用這份。

下表的「最佳行動」是 `fdps_map_actor_take_best_action`（`0x12c10`），回傳 1 表示已處理；「路徑最近」與「直線最近」是下一節的兩個移動 function，回傳 1 表示真的走了；「休息」是 `fdps_unit_rest`（`0x120d0`）。每一欄的步驟依序嘗試，前一步回 1 就停。

| 值 | 行為 |
| ---: | --- |
| 0 | 最佳行動 → 路徑最近 → 直線最近 → 休息 |
| 1 | 最佳行動 → 路徑最近 → 休息 |
| 2 | 最佳行動 → 休息。中間還會再跑一次物理攻擊評分，但那支永遠回 0，不影響結果；這個行為的單位不會為了接近對手而移動 |
| 3 | 最佳行動；沒行動時，以 `+0x35` 當角色編號找人（`fdps_battle_find_unit_by_character_id`（`0x2dc20`）：索引最小、角色編號相符、未退場的單位，不分陣營）。找到就朝那個單位的所在格移動，一步都走不了就休息；找不到就走行為 0 的移動部分：路徑最近 → 直線最近 → 休息 |
| 4 | 不評分，朝 (`+0x35`, `+0x36`) 移動，一步都走不了就休息 |
| 5 | 搶寶箱，見下 |
| 6 | 什麼都不做 |
| 7 | 不評分，朝 (`+0x35`, `+0x36`) 移動，一步都走不了就休息；移動後若所在格正好是目的地，肖像編號 `0x24`–`0x27` 的單位先播 `Posion.saf`，然後退場（內嵌的整 byte 指派把旗標 byte **整個寫成 1**，與 `fdps_unit_mark_retired`（`0x138f0`）同形，原版映像中沒有呼叫它） |
| 8 | 什麼都不做，而且連回合結尾都跳過 |
| 9 | 先以 `+0x35` 找人。找到就朝他移動，一步都走不了才依序試最佳行動 → 路徑最近 → 直線最近 → 休息；找不到就是最佳行動 → 路徑最近 → 直線最近 → 休息。沒有任何部署記錄或程式寫入讓單位進入這個模式，見 [`../cut_content/code.md`](../cut_content/code.md) 的 C2 |
| 10 | 道具評分達 6 就使用道具；**接著無論用了沒有**，再跑物理攻擊評分，達 6 就移動並攻擊，否則路徑最近 → 休息 |
| 11 | 肖像編號 `0x3c`–`0x3e` 的單位先呼叫 `fdps_chapter_30_revive_wave_4_undead`（`0x10760`，第 30 章的不死復活，見 [`../chapters/ch30.md`](../chapters/ch30.md)）；然後法術評分達 6 就施法；**接著無論施了沒有**，再跑物理攻擊評分，達 6 就移動並攻擊，否則路徑最近 → 休息 |
| 12–15 | 什麼都不做 |

行為 10 與 11 不經過 `fdps_map_actor_take_best_action`，所以同一個回合可以先用道具（或施法）再移動攻擊，一回合做兩件事。

除了行為 8 與已退場的單位，其餘每個值（包括什麼都不做的 6、12–15）最後都走同一段回合結尾：以單位現在的所在格呼叫 `fdps_map_set_pending_tile_event`（`0x2e030`），時機參數 1（在這格**結束回合**），標記本回合已行動（旗標 `|= 0x80`），重畫一幀。

### 行為 5：搶寶箱

1. 先跑最佳行動，有行動就結束。
2. 若自己事件碼（`+0x3d`）的觸發旗標已設，或 `fdps_map_find_chest_cell`（`0x13e10`）找不到寶箱，就改走行為 0 的移動部分（路徑最近 → 直線最近 → 休息）。
3. 否則朝寶箱格移動，一步都走不了就休息。移動後若所在格正好是寶箱格：讀地圖區塊中該事件碼的可搜尋格記錄（種類與運算元），種類小於 2 時把兩者複製成自己的死亡腳本（`+0x31`、`+0x32`），種類 0 另外把運算元當物品編號放進自己背包（`fdps_unit_add_item`（`0x25d20`））；不論種類，都設觸發旗標、套用格子變化（`fdps_map_apply_triggered_cell_changes`（`0x2e910`））、把 AI 行為 byte **整個寫成 7**（高 4 bit 一併清掉）、播 `Chess.wav`。

之後它就是行為 7：走向 `+0x35`／`+0x36` 的目的地，到了就退場。可搜尋格記錄的格式與死亡腳本 opcode 見 [`../resource_info/map.md`](../resource_info/map.md)。

`fdps_map_find_chest_cell`（`0x13e10`）逐列（外圈 y、內圈 x）掃描整張移動網格的尺寸，回傳第一格「屬性 `& 0x60` **等於** `0x20`、事件碼等於自己的事件碼」的座標。條件是等式，所以屬性 `0x60` 的格與埋藏格（`0x40`）都不算；玩家的搜尋指令接受的集合比這個寬。屬性旗標的意義見 [`../resource_info/terrain.md`](../resource_info/terrain.md)。

## 移動與休息

**路徑最近的對手**，`fdps_map_actor_move_toward_nearest_reachable_opponent`（`0x126b0`）：

1. 從單位所在格以移動力 100 擴散整張地圖，**不先標任何控制區**。擴散用的職業表列是 `fdps_get_class_record(職業)`，**沒有**其他地方一律加上的 +1，所以拿到的是前一個職業的地形消耗（原版錯誤，見 [`known_bugs.md`](known_bugs.md)）。
2. 以路徑追蹤的模式 2 找「陣營 ≠ 0、未退場、所在格可達」的單位中累積消耗最小者，同消耗取索引小的。這裡的陣營條件寫死，不看 `side_select`。
3. 找不到回 0；找到的單位就站在自己所在格（消耗 0）也回 0。否則呼叫 `fdps_battle_move_unit_toward`（`0x119e0`）朝那個單位的所在格走，那支會改成走到能停的格裡離目標最近的一格；有走才回 1。

第 2 步的寫死條件讓友軍眼光的單位（NPC 階段、陣營 1）永遠找到**自己**，所以 NPC 從來不靠這支移動：行為 0、3、5、9 的 NPC 落到直線最近，行為 1、10、11 的 NPC 直接休息（原版錯誤，見 [`known_bugs.md`](known_bugs.md)）。

**直線最近的對手**，`fdps_map_actor_move_toward_nearest_opponent`（`0x127c0`）：掃過全部單位（包括自己），保留陣營符合上面換算表、且未退場（只看旗標 bit 0）的，距離是 `|Δx| + |Δy|`，嚴格小於才取代，所以同距離取索引小的。沒有候選回 0；得勝者站在自己所在格回 0；否則朝那格走，有走才回 1。它完全不看地形，挑出的對手可能隔著走不過去的地形。

**休息**是 `fdps_unit_rest`（`0x120d0`），與玩家的休息指令同一支；何時什麼都不做、回復量怎麼算見 [`battle.md`](battle.md)。

## 最佳行動的選擇

`fdps_map_actor_take_best_action`（`0x12c10`）依序跑物理攻擊、法術、道具三個評分，然後以三個分數 P（物理，`0x63f78`）、S（法術，`0x63f88`）、I（道具，`0x63f8c`）做**五個明寫的比較**，不是取最大值：

1. 三者都 `< 6` → 不行動，回 0。
2. 否則依序：
   1. `P > S` 且 `P > I` → 移動並攻擊。
   2. `P == S` 且 `S > I` → 若選中的法術編號 `< 0x12`：`攻擊者攻擊力 − 物理目標防禦力 > 法術威力`（兩個字都是帶號 16 位元，法術威力是 `MAGICDAT.DAT` `+0x00` 的帶號字）就攻擊，否則施法。法術編號 `>= 0x12` 時看行為 byte 的 bit `0x40`：0 施法，1 攻擊。
   3. `P == I` 且 `I > S` → bit `0x40` 為 0 用道具，為 1 攻擊。
   4. `S > P` 且 `S >= I` → 施法。
   5. `I > P` 且 `I > S` → 用道具。
3. 只要進了第 2 步，不論上面有沒有任何一條成立，都把游標繪製模式設成 0 並回 1。

三個分數**完全相等且至少達 6** 時五條都不成立，單位什麼都不做，卻回報已行動，於是呼叫端不再嘗試移動或休息（原版錯誤，見 [`known_bugs.md`](known_bugs.md)）。

比較全部是帶號的。第 2.2 條的「攻擊力 − 防禦力」在任何分支之前就先算好，用的物理目標索引（`0x63f74`）在物理評分沒找到目標時是前一個單位留下的舊值；這個估計值只在 P ≥ 6 的平手分支裡用得到，那時索引一定是新的。部署記錄產生的單位 bit `0x40` 恆為 0：部署記錄的行為 byte 高 4 bit 全是 0，章節事件改行為時保留原本的高 4 bit，所以正式章節裡兩種平手一律歸法術、歸道具。行為 byte 的另一個來源是名冊：`fdps_roster_add_character`（`0x23bc0`）不寫 `+0x34`，名冊成員帶著名冊區塊原有的內容。一般章節的名冊成員是陣營 2，不會以行動者的身分走進地圖 AI；標題示範戰（`fdps_title_demo`）則把我方 12 格改成陣營 1 交給 AI，改模式時只換低 4 bit，所以示範戰裡這兩條平手的歸屬取決於殘值。下面補 HP 評分讀的是**目標**的 bit `0x80`，目標是名冊成員時（見 [`known_bugs.md`](known_bugs.md) 第 5 條，敵人拿神聖之水補我方）那一 bit 取決於殘值。這兩個高位旗標的來歷見 [`../cut_content/code.md`](../cut_content/code.md) 的 C3。

## 物理攻擊評分

`fdps_map_actor_score_best_attack`（`0x12230`）一進來就把 P 清成 0。單位沒有裝備武器（`fdps_unit_find_equipped_slot`（`0x25140`）的第 0 類回 -1）就直接結束，其餘三個決策全域（落腳格 `0x63f80`／`0x63f84`、目標索引 `0x63f74`）保留前一個單位的值。

**落腳格**：先標出對方陣營的控制區，再以單位自己的移動力（`+0x3b`）、`fdps_get_class_record(職業 + 1)` 的地形消耗從所在格擴散，最後把己方其他單位佔住的格拿掉（自己的格保留，所以「不動」也是候選）。剩下的格依列優先順序逐一當成候選落腳格。擴散規則見 [`movement.md`](movement.md)。

**每一格的目標**：以 `fdps_collect_targets_in_range(格, 武器最大射程, 武器最小射程, 模式)` 收集，模式在 `side_select == 0` 時是 1、否則是 0。射程取武器記錄 `+0x0c`（最大）與 `+0x0b`（最小），結果就是與落腳格 `最小射程 <= |Δx| + |Δy| <= 最大射程` 的對方單位（網格此時已重設，見「目標收集」）。最大射程 0 的武器（`63` 光束砲）只涵蓋落腳格本身，永遠打不到人。

**每個目標的估計**（A、D 是攻擊者的攻擊力與防禦力，a、d、h 是目標的攻擊力、防禦力、現有 HP，全部以帶號 16 位元讀入）：

```
E    = A - d
tier = (E > 2) ? 8 : 0
if (h < E) {             // 帶號比較，h 恰等於 E 不算擊殺
    E    = E * 2
    tier = 0x12
}
if (fdps_check_can_counter_attack_from_tile(目標, 落腳格) == 1)
    E = E + (D - a)      // 會被反擊時，加上「自己的防禦 − 對方的攻擊」
if (目標角色編號 == 0)    // 蘭迪斯
    E = (E * 3) / 2      // 帶號除法，向零截斷：5 → 7，-5 → -7
```

注意擊殺判定用的是反擊修正前、乘 2 前的 E；E ≤ 2 但目標 HP 更低時一樣是 `0x12`。

**排名**：`tier > P`，或 `tier == P` 且 `E > 目前最佳 E` 才取代；目前最佳 E 在 function 開頭是 0。取代時寫入落腳格、目標索引與 P = tier。比較是嚴格大於，所以同分時列優先順序較前的格、索引較小的目標保留。**發布的分數是 tier（0、8、`0x12`），不是 E**；E 只用來在同一 tier 內排序。

`fdps_map_actor_behavior_step`（`0x10010`）的行為 2 會測這支的回傳值，但它兩條路徑都回 0。

## 道具評分

`fdps_map_actor_score_best_item`（`0x13040`）一進來把 I 清成 0，背包數由 `fdps_unit_item_count`（`0x25240`）算出，0 就結束。接著以**迴圈計數當物品欄索引**走 `0 .. 數量-1` 個欄位（記錄 `+0x0b + 欄位 * 2` 的物品編號），不再看欄位旗標；裝備中的武器與防具也在這些欄位裡，一樣參與評分。物品欄中間若有空洞，最後一件會被略過、空洞那格會被讀進來；出貨的部署記錄建出來的物品欄沒有空洞。

每件物品：

1. `use_effect`（`+0x0d`）為 0 就跳過。
2. **瞄準格**：`use_distance`（`+0x10`）≤ `0x0f` 時是 `|Δx| + |Δy| <= use_distance` 的格（範圍收集器的菱形，含自己所在格）；≥ `0x10`（直線型）時是自己上下左右四格（範圍 1、最小距離 1）。
3. 每個瞄準格：收集模式照「side_select 與目標陣營」的換算；`use_distance` < `0x10` 時以 `fdps_collect_targets_in_range(瞄準格, use_radius（+0x12）, 0, 模式)` 收集，否則以 `fdps_collect_targets_in_line(瞄準格, 自己所在格, use_distance − 0x10, 模式)` 收集。
4. 有目標就以 `fdps_score_targets_for_item`（`0x132b0`）計分，**嚴格大於** I 才取代，寫入瞄準格（`0x63f98`／`0x63f94`）、欄位索引（`0x63f7c`）與 I。

`fdps_score_targets_for_item`（`0x132b0`）只認兩種 `use_effect`，其餘一律 0 分：

| `use_effect` | 每個目標的分數 |
| --- | --- |
| `0x0b`（補 HP 的消耗品） | `h <= hp_max / 3` → 8；否則 `h <= hp_max / 2` → 3；否則 0。目標行為 byte 的 bit `0x80` 為 1 時乘 3。h 與 hp_max 都帶號，兩個除法都向零截斷 |
| `0x1e`（光束砲、火焰） | `(無號 h) <= use_amount（+0x0e，帶號）` → `0x12`；否則 8 |

總分是各目標分數相加。所以 AI 只會用補 HP 的消耗品與兩種光束道具；屬性寶珠、帶效果的武器、補 MP、解狀態與能力提升的道具在 AI 手上永遠不會被使用。四種補 HP 道具不論回復量多少都同分。

`神聖之水`（`C2`，回復 1000）的對象 byte 是 0，其餘補 HP 道具（`B4`–`B6`）是 5。敵方眼光把 0 反轉成模式 1，於是持有神聖之水的敵人把它用在**我方與 NPC**身上；NPC 眼光直接用 0，把它用在敵人身上（原版錯誤，見 [`known_bugs.md`](known_bugs.md)）。它的使用距離是 1，自己所在格上只有自己、不符合模式，所以實際的對象是上下左右相鄰、`h <= hp_max / 3` 的對方單位（8 分），只要沒有能擊殺的攻擊（`0x12`），也沒有分數不低於它的法術，就會選它。出貨資料裡帶神聖之水的 AI 單位是第 24 章（`MAP23`）的 26 個敵人與第 26 章（`MAP25`）的 4 個 NPC，兩批在正常遊玩中都會出場：前者是波次 4，由回合事件 `fdps_chapter_24_event_deploy_wave_for_turn`（`0x38cc0`）在固定回合部署；後者是波次 3，由 `fdps_chapter_26_event_deploy_waves_2_and_3`（`0x39230`）在我方單位觸發該章的格子事件時部署（各章的事件內容見 [`../chapters/_index.md`](../chapters/_index.md)）。對象 byte 5 在 NPC 眼光下是模式 5，不對應任何陣營，所以 NPC 永遠不會使用 `B4`–`B6`。

## 法術評分

`fdps_map_actor_score_best_spell`（`0x13420`）一進來把 S 清成 0。單位不會任何法術，或封魔計時器（`+0x27`）非 0，就結束；已會的法術由 `fdps_unit_collect_known_spells`（`0x27840`）依編號由小到大列出。

每個法術：

1. MP 消耗（`+0x05`，無號）`>` 現有 MP（帶號）就跳過；剛好相等可以施放。
2. **中心格**：在剛重設的網格上以職業表第 0 列（各地形消耗 1）從自己所在格擴散，步數是施放距離 byte（`+0x03`）的**原值**，所以是 `|Δx| + |Δy| <=` 該值的菱形，含自己所在格。直線型法術的 `0x10` 旗標沒有拆掉，所以施放距離 `0x17` 的法術會被當成 23 步的範圍。出貨資料裡沒有任何 AI 單位會這類法術：部署記錄沒有；標題示範戰的我方 12 格由 `fdps_roster_add_character`（`0x23bc0`）以 `FRIAPRDA.DAT` 的初始法術遮罩建出，再加上 `萬神降臨`（`27`）與 `封神裂震`（`0B`），全部不是直線型（遮罩內容見 [`../assets/characters.md`](../assets/characters.md)）。
3. 每個中心格：收集模式照「side_select 與目標陣營」的換算，以 `fdps_collect_targets_in_range(中心格, 半徑（+0x04）, 0, 模式)` 收集。
4. 有目標就以 `fdps_score_targets_for_spell`（`0x13920`）計分。`分數 > S`，或 `分數 == S` 且法術威力（`+0x00` 帶號）`>` 目前最佳威力，才取代，寫入中心格（`0x63f9c`／`0x63fa0`）、法術編號（`0x63f90`）與 S。威力是帶號，八個以攻擊力倍率表示的絕招存成負數，同分時一定輸給一般法術。

`fdps_score_targets_for_spell`（`0x13920`）依法術編號分派，第一條是範圍，其餘都是等式，比對順序如下：

| 法術編號 | 每個目標的分數 |
| --- | --- |
| `0x0e`–`0x10`、`0x21`（恢復之光、治癒之風、痊癒之泉、鎮魂之歌） | `h < hp_max / 3` → 8；否則 `h < hp_max / 2` → 3；否則 0。目標行為 byte 的 bit 0 為 1（行為代碼是奇數）時乘 2。h 與 hp_max 以**無號**讀入 |
| `0x11` 封魔咒術 | 目標會至少一個法術**且**封魔計時器為 0 → 6 |
| `0x12` 腐毒術 | 中毒計時器（`+0x25`）為 0 → 10 |
| `0x18` 甦癒術 | 中毒、麻痺、封魔三個計時器任一非 0 → 6 |
| `0x13` 麻痺術 | 麻痺計時器（`+0x26`）為 0 → 10 |
| `0x14` 神之祝福 | 敏捷祝福計時器（`+0x24`）為 0 → 4。另外兩次攻擊、防禦祝福（`+0x22`、`+0x23`）的計算結果被後一次**覆寫**，不計入 |
| 其他全部（含 `0x0d`、`0x15`–`0x17`） | `0x0a`／`0x0b`（裂地術、封神裂震）先略過會飛的目標（`fdps_unit_is_flying`（`0x12550`）非 0），完全不計分。其餘：`h < 威力`（h 帶號）→ `0x18`，否則 8；目標角色編號為 0 時乘 1.5 後截斷（浮點運算，8 → 12、`0x18` → `0x24`） |

後果：傳送術、神行術威力 0，每個目標都拿 8 分；咒殺術威力 9999，每個目標都算擊殺 `0x18`，會咒殺術的敵人（第 19、23 章）幾乎總是想施放它。三個以 `fdps_score_targets_without_status`（`0x13c20`）計分的分支只算「計時器 byte 為 0 的目標數 × 單位分數」。

補 HP 的門檻在道具與法術之間**不同**：道具是 `<=`、帶號，法術是 `<`、無號；加權也不同（道具看 bit `0x80` 乘 3，法術看 bit 0 乘 2）。

## 目標收集

三個收集器都回傳收到的單位數，並把單位索引（每個 1 byte；範圍與區域收集器依索引由小到大，直線收集器依沿線由近到遠）寫進呼叫端的緩衝區；三者都不檢查緩衝區容量。

**範圍**，`fdps_collect_targets_in_range`（`0x11e50`）。在移動網格上標出範圍，再挑出站在標記格上的單位。呼叫前網格必須已重設，呼叫端事後自己重設。

- `range_code < 0x10`：以 `fdps_move_grid_flood_fill_range`（`0x10de0`）和職業表第 0 列（八種地形消耗全是 1）從中心擴散 `range_code` 步，範圍**含端點**。這一列沒有 `FF` 地形，擋得住擴散的只剩網格上的 `0x40` 旗標；AI 的每一次呼叫之前網格都剛重設、沒有任何旗標，所以對 AI 而言範圍就是地圖內 `|Δx| + |Δy| <= range_code` 的菱形。`min_dist` 非 0 時再把 `|Δx| + |Δy| < min_dist` 的格去掉（**嚴格小於**，所以 1 只去掉中心格）。
- `range_code >= 0x10`：十字形，中心所在的列與行上距離 `<= range_code − 0x10` 的格，不看地形，`min_dist` 不作用。
- 單位條件：未退場、所在格有標記，而且符合模式：

| 模式 | 收的單位 |
| ---: | --- |
| 0 | 陣營 0 |
| 1 | 陣營 ≠ 0 |
| 2 | 陣營 1 |
| 3 | 陣營 2 |
| 其他 | 無 |

**直線**，`fdps_collect_targets_in_line`（`0x13670`）。從起點格（施放者所在格）朝瞄準格走 `line_length` 步：起點與瞄準格同一行時沿 y 軸走，否則沿 x 軸走，**y 的差完全忽略**，所以永遠是正交直線。第一步就先移動，起點格本身不檢查；超出地圖的格跳過但不中止。每格以地圖游標查該格的單位（查詢本身排除已退場單位），陣營條件和上表**相反**：`select_enemy_side == 0` 收陣營 ≠ 0，非 0 收陣營 0。

**區域**，`fdps_collect_targets_in_area`（`0x109f0`）。只有玩家操作的游標選擇迴圈（`fdps_map_cursor_select_loop`（`0x2b4f0`））用它，AI 不用。條件是未退場且 `|Δx| + |Δy| < max_dist`（嚴格小於，呼叫端已先減 1），模式表是它自己的：0 收陣營 0、1 收陣營 ≠ 0、**2 收陣營 2 且本回合已行動**、3 收陣營 2。緩衝區給 NULL 時照樣計數。

範圍與直線收集器也被玩家的攻擊、道具、法術指令使用，規則相同。

## 反擊可行性

兩支判斷同一件事，一支問「如果攻擊者站在這格」，一支問兩個已在地圖上的單位。兩者都回傳 1（會反擊）或 -1（不會），**從不回 0**，四項測試依序、任一失敗即回 -1：

1. 防守方的麻痺計時器（`+0x26`）非 0。
2. `|Δx| + |Δy| != 1`（只有上下左右相鄰才反擊，對角與同格都不算）。
3. 防守方沒有裝備武器。
4. 武器最小射程（`+0x0b`）的判斷不同：

| function | 通過條件 |
| --- | --- |
| `fdps_check_can_counter_attack_from_tile`（`0x125c0`），AI 評分用 | 最小射程 `< 2`（0 或 1） |
| `fdps_check_can_counter_attack`（`0x137e0`），實際交戰與畫面顯示用 | 最小射程 `== 1` |

最大射程兩支都不看。兩者只對最小射程 0 的武器（出貨資料只有 `63` 光束砲）意見不同：AI 以為持光束砲的單位會反擊並把反擊代價算進評分，實際交戰時他不會反擊。

## 行動的執行

三支執行 function 不做任何決定，全部讀評分留下的全域，所以沒先跑對應評分就呼叫會執行舊的決定。

**移動並攻擊**，`fdps_map_actor_move_and_attack`（`0x12e50`）：

1. 游標模式 0，朝評分選的落腳格移動；游標模式 1，游標移到目標，攻擊者轉向目標，停 100 ms。
2. 經驗值暫存（`0x69cec`）清 0。
3. 戰鬥動畫開關（`0x60010`）為 0 時在地圖上直接結算：反擊判定為 1 則目標轉向攻擊者；攻擊者出手；**目標沒死而且**反擊判定為 1（兩個條件都先算出來再做位元 AND，第二次判定一定會呼叫）就雙方互相轉向、目標反擊。開關非 0 時改播完整的交戰畫面 `fdps_combat_play_attack_exchange`（`0x18d60`）。
4. 收集死亡腳本（`fdps_collect_death_scripts`（`0x26180`）），播死亡動畫，以**目標**的索引當擊殺者執行 `fdps_run_death_scripts`（`0x1d990`）。
5. `經驗值暫存 = 經驗值暫存 * 15 / 10`（帶號，向零截斷），交給**目標**的 `fdps_unit_award_exp_and_level_up`（`0x1dd30`）。這是我方單位在敵方回合挨打時靠反擊得到經驗值的路徑；經驗值怎麼累積見 [`battle.md`](battle.md)。
6. 回 1。

**施法**，`fdps_map_actor_cast_chosen_spell`（`0x13c90`）：S `< 6` 就不施法、回 0。否則以評分時的同一組模式與半徑重新收集中心格的目標，游標以模式 `半徑 + 2`（範圍菱形）移到中心格、停 200 ms；戰鬥動畫開關**等於 1** 時播完整法術畫面（`fdps_combat_play_spell_on_targets`（`0x1a4c0`）），其他值一律在地圖上結算（`fdps_cast_spell_on_targets`（`0x288f0`））。之後以 `fdps_collect_death_script_events`（`0x274e0`）收集死亡腳本並執行（它只收 opcode 2–5，被法術打倒的單位的物品與金錢掉落不發放，見 [`battle.md`](battle.md)），擊殺者參數是**物理評分的目標索引** `0x63f74`，不是施法者：經由最佳行動施法時是這個單位的物理評分剛選的目標（沒選到目標時是舊值），經由行為 11 施法時物理評分還沒跑，是前一個單位留下的值；經驗值暫存清 0，所以法術擊殺不給任何人經驗值。這個錯位在出貨資料中不改變任何結果：擊殺者索引只有 opcode 2 會交給章節處理函式，而出貨的死亡腳本 opcode 2 指到的處理函式裡會讀這個參數的只有 `fdps_chapter_22_event_boss_defeat`（`0x388b0`）與 `fdps_chapter_23_event_boss_defeat`（`0x38950`），兩者掛在陣營 0 的頭目身上；敵方眼光下所有傷害法術（對象 byte 0）都換算成收陣營 ≠ 0，打不到陣營 0，而那兩章沒有任何會法術的陣營 1 單位。法術本身的效果與 MP 扣除見 [`spell.md`](spell.md)。

**用道具**，`fdps_map_actor_use_item`（`0x27180`）：沒有分數門檻（由呼叫端先測：行為 10 與最佳行動）。以評分時的同一組模式重新收集目標（直線型用直線收集器、長度 `use_distance − 0x10`，其餘用範圍收集器、半徑 `use_radius`），停 200 ms。

- 範圍型：游標以模式 `use_radius + 2` 移到瞄準格。游標模式沒有被改回來：經由最佳行動時由 `fdps_map_actor_take_best_action` 返回前清成 0，經由行為 10 時由接著的動作或階段迴圈清掉。
- 直線型：轉向第一個目標、停 200 ms，全畫面白光從 `0x40` 逐步降到 0（每步 4 ms），然後游標以軌跡模式 6 從施放者所在格掃到「施放者格 + `(use_distance − 0x10)` ×（瞄準格 − 施放者格）」並停 8 幀。這個終點的夾限讀錯了邊界，朝右或朝下超出地圖的光束，軌跡會掃到地圖外，模式 6 的標記落到下一列的格上或移動網格區塊之後（原版錯誤，成因見 [`known_bugs.md`](known_bugs.md) 第 9 條）。軌跡只是畫面，命中的目標在收集時就決定了。
- 最後以 `fdps_apply_item_effect_to_targets`（`0x262a0`）套用效果，經驗值暫存清 0，回 0。

## 原版錯誤一覽

機制寫在 [`known_bugs.md`](known_bugs.md)，這裡只列出處：

- 路徑最近的對手用了前一個職業的地形消耗：`fdps_map_actor_move_toward_nearest_reachable_opponent`（`0x126b0`）。

- 神聖之水在敵人手上補我方、在 NPC 手上補敵人：`fdps_map_actor_score_best_item`（`0x13040`）、`fdps_map_actor_use_item`（`0x27180`）。
- 光束道具的軌跡夾限拿錯邊界：`fdps_map_actor_use_item`（`0x27180`）。

重建時照直覺寫就會與原版不同的地方收在 [`../rebuild_info/pitfalls.md`](../rebuild_info/pitfalls.md)。

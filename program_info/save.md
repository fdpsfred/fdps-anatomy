# 存讀檔流程

**驗證對象**：`FDPS.LE` 的存讀檔流程——戰鬥中系統子選單 `0x14ea0`（存檔、讀檔兩個分支與兩個項目的反灰判定，`src/btlmenu.c`）、戰鬥存檔的讀回 `0x23e20`（`src/savefile.c`）、存檔畫面與讀檔畫面 `0x241e0`、`0x24490` 與兩者共用的 slot 游標 `0x24650`（`src/save.c`）、存讀檔版面 `0x24830`、`0x24a40`（`src/savepnl.c`），以及標題畫面 `0x2a2b0` 裡決定「讀檔」「繼續」能不能選的存檔閘門與這兩項的分派（`src/title.c`）。這些 function 在什麼時機被叫到、寫出與讀回哪些遊戲狀態、讀完之後遊戲從哪裡接下去，以本頁為唯一正典。`FDE.SAV` 的位元組佈局、各欄位的偏移、檢查碼與加密算法（`0x56898`、`0x568b7`）屬於 [`resource_info/save.md`](../resource_info/save.md)，本頁不重複；村莊階段與酒館本身屬於 [`village.md`](village.md)，章節的進入與結束屬於 [`chapter.md`](chapter.md)。

## 兩種存檔

`FDE.SAV` 裡有兩種互不相干的存檔，由不同的選單寫、不同的程式讀：

| | 戰鬥存檔 | 章節 slot |
| --- | --- | --- |
| 份數 | 1 份，每次覆蓋 | 畫面上 3 格（檔案有 4 格，第 4 格沒有畫面選得到） |
| 內容 | 整場戰鬥：地圖腳本區塊、名冊、地圖單位陣列、事件旗標、回合與游標 | 章節之間的隊伍：名冊、章節、金錢、四個選項開關、存檔時刻、抽獎旗標 |
| 寫入 | 戰鬥中系統子選單的「存檔」，`fdps_battle_system_submenu`（`0x14ea0`） | 存檔畫面 `fdps_save_game_screen`（`0x241e0`） |
| 讀回 | `fdps_load_savegame`（`0x23e20`），由系統子選單的「讀檔」與標題選單的「繼續」叫 | 讀檔畫面 `fdps_load_game_screen`（`0x24490`），由標題選單的「讀檔」與酒館的「讀檔」叫 |
| 讀回後從哪裡繼續 | 存檔當時那一回合的玩家階段開頭 | 該 slot 記的章節的村莊階段（或無村莊章節的開戰） |

兩條寫入路徑都是「整檔讀進來、只改自己那一區、重算檢查碼、整檔加密寫回」，所以寫一種存檔會原樣保留另一種。檔案不存在時兩者各自造初始映像的方式不同，見 [`resource_info/save.md`](../resource_info/save.md)。

## 什麼時候能存、能讀

### 戰鬥中

地圖上沒有選單位時打開的戰鬥選單第一項是系統子選單 `fdps_battle_system_submenu`（`0x14ea0`），四項依序是勝敗條件、存檔、讀檔、離開。子選單一打開就決定兩個項目要不要反灰，之後整個子選單開著的期間不再重算：

- **存檔反灰**：地圖單位陣列裡只要有任何一個單位「未退場（`flags` bit 0 為 0）而且本回合已行動（`flags` bit 7 為 1）」就反灰。迴圈走完整個陣列不提早離開。所以只有在這一回合還沒有任何單位行動時能存，戰鬥存檔永遠是「某回合玩家階段開頭」的狀態。
- **讀檔反灰**：`access("FDE.SAV", 0)` 回非 0（檔案不存在）時反灰。只看檔案在不在，不看裡面有沒有戰鬥存檔，也不驗檢查碼。

反灰的項目在環狀選單上連游標都移不過去（環狀選單的行為見 [`battle.md`](battle.md)）。選了存檔或讀檔都會先開訊息窗（臉圖 0）問一次，確認用 `fdps_prompt_two_choice`，回 0 才算「是」：

| 項目 | 問句 | 答「是」 | 停留 | 答「否」 | 停留 |
| --- | --- | --- | --- | --- | --- |
| 存檔 | 全域文字 `0x1f3` | 寫檔後印 `0x203` | 200 ms | 印 `0x204` | 300 ms |
| 讀檔 | `0x205` | 印 `0x206`、關窗後讀檔 | 200 ms | 印 `0x207` | 300 ms |

兩個分支結束後都清空鍵盤佇列、回 0，戰鬥選單隨之關閉，回到玩家階段迴圈。

### 章節之間

`main`（`0x29220`）在結束碼 2（過關）時先跑該章的結束處理函式、再進 `fdps_run_village_phase`（`0x31210`）。結束處理函式已經把章節索引改成下一章，所以這之後存的 slot 記的是**下一章**（[`chapter.md`](chapter.md)）。村莊階段依下一章有沒有村莊分兩條路：

- **無村莊的章節**（章節索引 `0x10`、`0x11`、`0x15`、`0x16` 與大於 `0x19` 的全部）：畫面清黑、載入主調色盤，直接開存檔畫面，交給它一張全黑的頁面當收尾背景。這一步只在 `data_fdps_village_skip_save_prompt_flag` 為 0 時發生。
- **有村莊的章節**：存讀檔只在酒館，`fdps_run_bar_shop`（`0x35cc0`）的指令列是「交談、存檔、讀檔、離開」。存檔開存檔畫面，結束後一律回到指令列；讀檔開讀檔畫面，只有真的讀了（回 1）才結束這次酒館造訪。兩者都以酒館當下的畫面當收尾背景。

村莊階段的結尾會把 `data_fdps_village_skip_save_prompt_flag` 清回 0，不論有沒有用到它（[`village.md`](village.md)）。

### 標題畫面

`fdps_title_screen`（`0x2a2b0`）的選單四項依序是新遊戲、讀檔、繼續、離開。四項的狀態 byte 從映像裡的初值 `{0, 2, 2, 0}` 開始（0 可選、2 反灰），進入時跑一次存檔閘門：

1. `fopen("FDE.SAV", "rb")` 失敗 → 讀檔、繼續維持反灰。
2. 否則整檔讀進來、解密、以 `fdps_compute_save_checksum`（`0x56898`）重算檢查碼。**檢查碼相符而且戰鬥存檔的章節 byte 不是 `0xff`** 時，讀檔與繼續**一起**改成可選；任一條件不成立兩項都維持反灰。

閘門每次呼叫 `fdps_title_screen` 只跑一次，選單重新出現（讀檔畫面取消後、demo 之後）不會重跑。反灰的項目游標仍然移得上去，只是 Enter／Space 沒有反應。

這個閘門看的是**戰鬥存檔**的章節 byte，而「讀檔」讀的是 slot：從沒在戰鬥中存過檔、只在章節之間存過 slot 的玩家，開機後從標題選單進不了讀檔畫面，要先開新遊戲走到第一個村莊才讀得到自己的 slot，這是原版錯誤（[`known_bugs.md`](known_bugs.md) 第 16 條）。反過來，戰鬥存檔一旦寫過，章節 byte 就不會再變回 `0xff`（只有存檔畫面在檔案不存在時把整份映像填成 `0xff` 再寫出），所以「繼續」此後永遠可選、永遠讀回最後一次戰鬥存檔，不論那場戰鬥後來打到哪裡。

進入標題畫面時 `data_fdps_bonus_lottery_drawn_flag` 一律清成 0；讀檔畫面會從 slot 還原它，戰鬥存檔不帶它（見下方）。

## slot 選擇流程

存檔畫面與讀檔畫面共用同一套版面與游標，差別只在背景圖與「空格能不能選」。

### 版面

`fdps_saveload_screen_build`（`0x24830`）組出整張 320×200 的頁面交給呼叫端：

1. 從 `MISC.VFS` 取背景：存檔畫面是 `Save.cel`，讀檔畫面是 `Load.cel`，貼在頁面原點。
2. 讀 `FDE.SAV`：開得起來就整檔讀入並解密（**不驗檢查碼**、不看讀到多長）；開不起來就把整份映像填成 `0xff`、不解密。
3. 對 slot 0–2 各做一次：slot 的章節 byte 等於 `0xff` 就在 `data_fdps_ui_save_slot_occupied_flags[slot]` 寫 0（空格），否則寫 1；然後以 `fdps_draw_save_slot_panel`（`0x24a40`）把那一格的摘要畫在頁面的 (13, 26 + 52 × slot)。空格只印全域文字 `0x209`；有內容的格子印隊長頭像與等級、章號與章名、存檔的日／月與時：分——各欄位從 slot 的哪裡取見 [`resource_info/save.md`](../resource_info/save.md)。
4. 每畫一格有內容的 slot 都會清空 sprite 快取、只放那一格隊長的圖示群組，所以最後把快取再清一次，照名冊順序把每個成員的圖示群組重新載回。

檔案每次組版面都重讀，不快取，所以存檔畫面寫完一格後重組的版面會顯示剛寫的內容。

### 游標

兩個畫面進場時都以 `fdps_transition_random_blocks` 把頁面以 4×3 像素的方塊、16×16 的相位格、每換一格之間 `delay(1)`，馬賽克式地換上畫面，離場時以同樣的參數換回呼叫端交來的頁面。中間是 `fdps_save_slot_select_loop`（`0x24650`），每一幀從鍵盤環讀一個掃描碼：

| 按鍵（掃描碼） | 作用 |
| --- | --- |
| ↑ `0x48`、← `0x4b` | `slot = (slot + 2) % 3`，播 `Beep.wav` |
| → `0x4d`、↓ `0x50` | `slot = (slot + 1) % 3`，播 `Beep.wav` |
| Esc `0x01` | 取消，回 −1 |
| Space `0x39`、Enter `0x1c` | 存檔畫面：一律確定；讀檔畫面：該格的佔用旗標非 0 才確定。確定時播 `Sure.wav`、回 1 |

- 取餘數是帶號的 `IDIV`，往回走寫成 `+2` 而不是 `−1`，游標因此永遠留在 0..2。
- 掃描碼以帶號比較 `≥ 0x7f` 的一律忽略，所以鍵盤環空時的 `0xff` 不會被當成按鍵。
- 讀檔畫面對空格按確定**沒有任何反應**：不發聲、不提示，這一幀照常畫完。
- 其他畫面能取消的數字鍵盤 Del（`0x53`）在這裡不起作用，Esc 是唯一的出口。
- 每一幀只讀一個掃描碼，按住方向鍵時游標以畫面的幀率一格一格走。
- 決定之後還會再畫完一整幀才離開迴圈，所以留在畫面上的是游標停在所選格子的那一幀。

游標的高亮是 `LoadKon.cel` 的三張圖，畫在 (10, 25 + 52 × slot)；圖號是 `(tick >> 2) & 3`，其中 3 改成 1，所以每 4 個 timer tick 換一張、依 0、1、2、1 循環。每幀先等垂直回掃**結束**才把頁面整張搬上畫面，再等 timer tick 前進一格；上一幀的 tick 暫存沒有初值，第一幀不等。

`data_fdps_ui_saveload_is_load_mode` 決定空格能不能選：存檔畫面進場寫 0、讀檔畫面進場寫 1，兩者離場都不還原。

### 存檔畫面與讀檔畫面的差別

- **存檔畫面** `fdps_save_game_screen`（`0x241e0`）：游標進場時設在 slot 0，之後整個畫面期間保留上次的位置。每確定一次就寫一次檔、重組版面、再開一次游標，直到按 Esc 才離開——同一次造訪可以連存好幾格。空格與有內容的格子都能選，選有內容的格子直接覆蓋，不另外確認。畫面沒有回傳值，寫檔成功與否呼叫端看不到。
- **讀檔畫面** `fdps_load_game_screen`（`0x24490`）：游標進場時設在 slot 0，只跑一輪。確定就讀檔、回 1；Esc 回 −1。版面在讀檔之前就先釋放。

## 存檔寫出哪些狀態

### 章節 slot

`fdps_save_game_screen`（`0x241e0`）每次確定後依序：

1. 配置 `0x59cb` byte，`fopen("FDE.SAV", "rb")` 成功就整檔讀入、解密；失敗就整份填 `0xff`（不解密）。
2. 取目標 slot `image + 0x312b + slot × 0xa28`。
3. 先以 `_dos_getdate`、`_dos_gettime` 取當下日期時間，再把名冊區塊（`data_fdps_roster_array_ptr` 指向的 `0xa00` byte）整塊搬進 slot 開頭。
4. 在這 `0xa00` byte 的**最後 `0x14` byte 上**依序寫入月、日、時、分（DOS 結構的單一 byte 零延伸成 dword）與 `data_fdps_bonus_lottery_drawn_flag`，蓋掉名冊第 32 筆記錄的尾端（[`rebuild_info/pitfalls.md`](../rebuild_info/pitfalls.md)）。年份不存。
5. 其後寫入章節索引與名冊人數（兩個 `int` 全域各取低 byte）、隊伍金錢（整個 `int`）、地形資訊面板、戰鬥動畫、音樂、音效四個開關（各一 byte）。
6. `fopen("FDE.SAV", "wb")`，算檢查碼存進映像、整份加密、`fwrite`、`fclose`、釋放映像。寫入用的 `fopen` 不測；磁碟寫不進去時會在 CRT 裡出事，畫面照常繼續。

slot 不存地圖、單位陣列、回合數與事件旗標——它是章節之間的狀態，讀回後由該章的進入處理函式重新建立戰場。

### 戰鬥存檔

`fdps_battle_system_submenu`（`0x14ea0`）的存檔分支在玩家答「是」之後依序：

1. 配置 `0x59cb` byte，`fopen("FDE.SAV", "rb")` 成功就整檔讀入、解密；失敗時只把四個 slot 的章節 byte 寫成 `0xff`，其餘保留 `malloc` 的原樣內容。
2. 搬入四個區塊：地圖腳本區塊（`data_fdps_tile_event_data_table_ptr`，固定 `0x8a3` byte）、名冊（`0xa00` byte）、地圖單位陣列（`data_fdps_map_unit_count × 0x50` byte）、格子事件已觸發旗標（`0x20` byte）。
3. 填標頭：回合數、地圖單位數、章節索引、roster 人數各取低 byte；畫面視窗原點 x／y 與地圖游標 x／y 四個世界像素座標各以 `座標 / 24`（帶號除法、向零截斷）換成格數後取低 byte；`+0x07`、`+0x08` 恆寫 0；金錢整個 `int`；戰鬥動畫、地形資訊面板、音樂、音效四個開關。
4. **先** `fopen("FDE.SAV", "wb")`（舊檔從這一刻起已被截斷）、再算檢查碼存進映像、整份加密、`fwrite`、`fclose`、釋放。寫入用的 `fopen` 與 `fwrite` 的結果都不測。

戰鬥存檔**不帶**：酒館抽獎旗標、目前是哪個陣營的階段（存檔只可能發生在玩家階段開頭）、sprite 快取本身（單位記錄裡的槽號照樣存進檔案，但讀回時不用、重新配發）、地圖圖層與調色盤（讀回時從資源檔重新載入）。

## 讀檔後怎麼重建、從哪裡繼續

### 章節 slot 的讀回

`fdps_load_game_screen`（`0x24490`）在確定之後：

1. 配置 `0x59cb` byte、`fopen("FDE.SAV", "rb")`、`fread`、解密、`fclose`。`fopen` 的結果、讀到的長度與檢查碼**都不檢查**；正常遊玩碰不到檔案不存在的情況，因為兩個入口都已經先確認過（標題的閘門、讀檔畫面不讓選空格）。
2. slot 的前 `0xa00` byte 整塊搬回名冊區塊——連同寫在尾端的五個存檔戳記 dword 一起回到名冊第 32 筆記錄的尾端。
3. 章節索引、名冊人數（byte 零延伸成 `int`）、金錢、地形資訊面板、戰鬥動畫、音樂、音效四個開關（byte 對 byte）寫回全域。
4. **只有在 `data_fdps_village_mode_flag` 為 0（不在村莊階段中）時**才把抽獎旗標寫回 `data_fdps_bonus_lottery_drawn_flag`。從酒館讀檔時沿用本次執行當下的抽獎狀態，從標題讀檔時取存檔裡的值。
5. 讀進來的 `0x59cb` byte 映像**從不釋放**，每讀一次洩漏一次（[`rebuild_info/pitfalls.md`](../rebuild_info/pitfalls.md)）。
6. 馬賽克換回呼叫端交來的頁面，回 1。

地圖、單位陣列與事件旗標這裡都不碰。之後的去向看入口：

- **標題的「讀檔」**：`fdps_title_screen`（`0x2a2b0`）先配一張全黑頁面交給讀檔畫面，回來後**不論結果**把 `data_fdps_village_skip_save_prompt_flag` 設成 1。回 −1（取消）時讀檔畫面的回傳值被改成 0（視為還沒選定），選單整套重新載入後再出現，旗標仍留在 1。回 1 時直接在標題畫面裡呼叫 `fdps_run_village_phase`（`0x31210`）：讀進來的章節有村莊就進城鎮（商店是那一章的）；沒有村莊就因為上述旗標而跳過章節之間的存檔畫面。村莊階段的結尾呼叫該章的進入處理函式建立戰場，標題畫面隨後返回，`main` 進入戰鬥的玩家階段迴圈。
- **酒館的「讀檔」**：回 1 時 `fdps_run_bar_shop`（`0x35cc0`）呼叫 `fdps_load_field_chapter_resources`（`0x31540`）照新的章節重新載入章節文字、商店表，把名冊接成地圖單位陣列並重建 sprite 快取，然後結束這次酒館造訪。回到村莊階段後，讀進來的章節若沒有村莊，村莊階段隨即結束並進入該章；若有村莊，游標回到城鎮的招牌選單，照新章節的內容繼續逛。回 −1 時回到酒館指令列。

### 戰鬥存檔的讀回

`fdps_load_savegame`（`0x23e20`）依序：

1. 配置 `0x59cb` byte，失敗時印 `Out of Memory on get save buffer!!!` 並 `exit(1)`。
2. `fopen("FDE.SAV", "rb")`（結果不測）、`fread`、`fclose`、解密。
3. 重算檢查碼與 `+0x59c7` 比對。不符時開訊息窗（臉圖 0）、印全域文字 `0x208`、**不等按鍵**就關窗，然後照樣往下載入。從標題的「繼續」進來時閘門剛驗過同一個檔，這個分支只有從戰鬥中讀檔才可能走到。
4. 名冊 `0xa00` byte 搬回名冊區塊。
5. 釋放舊的主調色盤、從 `MISC.VFS` 重新載入 `Fde.pal`。
6. 章節索引寫回全域，**然後**呼叫 `fdps_field_load_chapter_resources`（`0x227e0`）照這個章節重新載入地圖、圖層與移動網格——它讀的是全域，所以章節必須先寫。
7. 釋放它剛載入的地圖腳本區塊，另配 `0x8a3` byte 換成存檔裡那一塊，並從**這塊**的 `+0x01`、`+0x02` 重新取出我方 slot 數與部署記錄筆數。
8. 舊的地圖單位數非 0 時釋放舊單位陣列；單位數改成存檔標頭的值，配置整塊 `0x1e00` byte（96 筆），搬回 `單位數 × 0x50` byte。單位數沒有上限檢查。
9. `0x20` byte 事件旗標搬回 `data_fdps_map_cell_event_triggered_flags`——章節處理函式借用它當一次性事件的閂鎖，所以讀檔後已觸發的事件不會再觸發（[`chapter.md`](chapter.md)）。
10. 清空 sprite 快取，開 `ICON.CEL` 為每個單位重新載入圖示群組，把新的槽號寫回記錄（檔案裡的槽號不用）。
11. 回合數、名冊人數（byte 零延伸）、金錢、四個開關寫回；畫面視窗原點與地圖游標四個座標以 `格數 × 24`（byte 零延伸後相乘）還原成世界像素。
12. 釋放映像，然後 `fdps_map_apply_triggered_cell_changes`（`0x2e910`）把已觸發格子的地圖變化重新套上、`fdps_render_view_frame`（`0x2beb0`）畫一幀、播 `PlyPhase.saf` 玩家階段橫幅、`fdps_cd_verify_disc_and_play_track`（`0x30cc0`）以該章的第一欄音軌開始播放——光碟不對時停在這裡等換片（[`cd_audio.md`](cd_audio.md)）。

抽獎旗標不在戰鬥存檔裡：從標題「繼續」時它是標題畫面剛清的 0，從戰鬥中讀檔時保留原值。

之後的去向：

- **標題的「繼續」**：`fdps_title_screen`（`0x2a2b0`）呼叫完 `fdps_load_savegame` 就結束選單並返回，`main`（`0x29220`）接著進 `fdps_battle_player_phase_loop`（`0x2bae0`），從存檔的回合的玩家階段接下去。
- **戰鬥中的「讀檔」**：`fdps_battle_system_submenu`（`0x14ea0`）讀完回 0，戰鬥選單 `fdps_battle_system_menu`（`0x14ab0`）把游標覆蓋與可操作旗標設回 1 後回 0，控制權回到原本的玩家階段迴圈，在已被整個換掉的戰場上繼續（[`battle.md`](battle.md)）。

## 原版錯誤

以下兩項的機制寫在 [`known_bugs.md`](known_bugs.md)，這裡只列出與存讀檔流程的關係：

- 標題選單的「讀檔」與「繼續」共用戰鬥存檔的解鎖條件，只存過 slot 的玩家從標題進不了讀檔畫面（`fdps_title_screen`（`0x2a2b0`）的閘門）。
- 在標題選單進讀檔畫面再取消，`data_fdps_village_skip_save_prompt_flag` 仍被設成 1、而且標題畫面不會清它；之後若以「繼續」接回一場戰鬥、打完進入的下一章沒有村莊，那一次章節之間的存檔畫面會被跳過（`fdps_run_village_phase`（`0x31210`）只在旗標為 0 時開存檔畫面）。

# 人物 record

四張表各自的一筆。數值見 [`assets/characters.md`](../characters.md)，檔案層面的事實見 [`resource_info/data_tables.md`](../../resource_info/data_tables.md)。

## 出場屬性 `FRIAPRDA.DAT`，24 byte

| 偏移 | 型別 | 欄位 | 內容 |
| ---: | --- | --- | --- |
| `0x00` | `u8` | `race` | 種族代碼 |
| `0x01` | `u8` | `clazz` | 職業代碼 |
| `0x02` | `u8` | `level` | 入隊（`fdps_roster_add_character`，`0x23bc0`）時的等級；地圖部署（`fdps_deploy_unit`，`0x232b0`）不讀這一欄，等級取自部署記錄 |
| `0x03` | `i16` | `hp_base` | 生命基礎值 |
| `0x05` | `i16` | `mp_base` | 法力基礎值 |
| `0x07` | `u8` | `move` | 移動力 |
| `0x08` | `u8[4]` | `spells` | 初始法術遮罩，bit 編號即法術編號，只涵蓋 `00`–`1F` |
| `0x0C` | `u8[6]` | `items` | 初始物品，`FF` 表示空槽 |
| `0x12` | `i16` | `ap_base` | 力量基礎值 |
| `0x14` | `i16` | `dp_base` | 耐力基礎值 |
| `0x16` | `i16` | `dx_base` | 速度基礎值 |

`hp_base`／`mp_base`／`ap_base`／`dp_base`／`dx_base` 五個都以 `MOVSX` 帶號讀入。

`items` 與 `spells` 只有入隊時讀，地圖部署的物品與法術取部署記錄。入隊時 `items` 的前兩槽一律標成「裝備中」，第 3–6 槽依值是否為 `FF` 標成空或持有中，第 7、8 槽固定為空。

## 升級成長 `FRILEVUP.DAT`，11 byte

| 偏移 | 型別 | 欄位 |
| ---: | --- | --- |
| `0x00` | `u8` | `ap_min` |
| `0x01` | `u8` | `ap_max` |
| `0x02` | `u8` | `dp_min` |
| `0x03` | `u8` | `dp_max` |
| `0x04` | `u8` | `dx_min` |
| `0x05` | `u8` | `dx_max` |
| `0x06` | `u8` | `hp_min` |
| `0x07` | `u8` | `hp_max` |
| `0x08` | `u8` | `mp_min` |
| `0x09` | `u8` | `mp_max` |
| `0x0A` | `u8` | `learn_index`，指向 `GETMGTAB.DAT` 的第幾筆，`FF` 表示不學法術 |

各 `*_max` 在大於 `*_min` 時是「最大成長值加 1」：每級成長落在 `*_min` 到 `*_max` 減 1，攻略站列的成長範圍上限就是這個 byte 減 1。兩者相等時每級固定成長 `*_min`（不抽亂數），攻略站列的也就是這個 byte 本身。

## 法術習得 `GETMGTAB.DAT`，12 byte

六組 2 byte，每組是「等級, 法術編號」，兩者皆 `FF` 表示這一組沒用到。60 筆全部符合同一個慣例：有內容的組排在前面，等級由小到大。

## 轉職路線 `RANKUP.DAT`，12 byte

對應 `src/fdpstype.h` 的 `struct fdps_promotion_record`。四組 3 byte，每組是一條轉職路線：

| 偏移 | 型別 | 欄位 | 內容 |
| ---: | --- | --- | --- |
| `0x00` | `u8[3]` | 路線 0 | 沒有徽章時的路線 |
| `0x03` | `u8[3]` | 路線 1 | 持有 `E0` 光之徽章 |
| `0x06` | `u8[3]` | 路線 2 | 持有 `E1` 暗之徽章 |
| `0x09` | `u8[3]` | 路線 3 | 肖像編號 `00`（蘭迪斯）持有 `DB` 勇者徽章；其餘八筆這一組全 0，不會被選到 |

每組的三個 byte：

| 偏移 | 內容 |
| ---: | --- |
| `+0` | 轉職後的型態，寫進單位記錄 `+0x07`（肖像編號）；也是升級時查 `FRILEVUP.DAT` 的索引 |
| `+1` | 轉職後的職業代碼，寫進單位記錄 `+0x20` |
| `+2` | 移動力加值，加到單位記錄 `+0x3B` |

取值函式 `fdps_get_promotion_record`（`0x18c30`）以單位記錄 `+0x08` 的角色編號索引，不是會被轉職改掉的 `+0x07`。檔案 108 byte 只有 9 筆（角色 `00`–`08`），沒有界限檢查，靠呼叫端只讓肖像編號小於 9 的單位轉職擋住。數值見 [`assets/characters.md`](../characters.md) 的「轉職路線」。

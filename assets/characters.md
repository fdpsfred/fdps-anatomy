# 人物

三張表共同決定一名我方人物的能力：`FRIAPRDA.DAT` 給基礎值與初始配備，`FRILEVUP.DAT` 給每級的成長範圍，`GETMGTAB.DAT` 給法術的習得等級。record 佈局見 [`tables/characters.md`](tables/characters.md)。

## 來源

數值全部出自三個 `.DAT` 的實際 byte。人物與職業的對應出自攻略站的升級屬性表與法術頁，並由 `RANKUP.DAT` 的轉職對照獨立佐證：該表 9 筆各含四組（習得索引, 職業代碼），對上的正是攻略站列的九名可轉職人物與各自的初級／光之徽章／暗之徽章／勇者徽章去向。

攻略站列出的 31 列升級成長、34 列法術習得、以及 12 名人物第一次出場的 LV／AP／DP／DX／HP／MP 全部與資料檔逐筆相符。

## 出場數值是基礎值加成長

表裡存的不是人物出場時的數值，而是基礎值；實際數值由 `FDPS.LE` 在建立單位時算出來，兩組欄位用的公式不一樣：

```
AP = ap_base + LV × ap_min
DP = dp_base + LV × dp_min
DX = dx_base + LV × dx_min
HP = hp_base + (LV - 1) × hp_min
MP = mp_base + (LV - 1) × mp_min
```

用到的是成長範圍的**最小值**，最大值只在升級時的亂數取值用得到。攻略站給的 12 名人物出場數值套上這組公式後與資料檔完全吻合，五個欄位、12 個人全中。

## 索引與習得索引

`FRIAPRDA.DAT`／`FRILEVUP.DAT` 的索引就是單位的肖像編號：地圖單位記錄裡的肖像編號小於 60 時走這兩張表，60 以上走 `ENEMYDAT.DAT`。`FRILEVUP.DAT` 的最後一個 byte 是**習得索引**，指向 `GETMGTAB.DAT` 的哪一筆，`FF` 表示這個職業不學法術。

真正有內容的索引是 `00`–`0B`（十二名人物的初級型態）、`0F`–`23`（轉職後的型態）與 `3B`。攻略站列到 `21` 為止，`22`、`23`、`3B` 三筆它沒有列。

其餘索引在 `FRILEVUP.DAT` 裡是全 0，唯一的例外是 `0C`：那一筆的十個成長值一律是 1、習得索引是 `FF`，形狀像預設值而不是填充。

`FRIAPRDA.DAT` 的 60 筆則不是 60 組角色屬性。逐 byte 比對後，只有 `00`–`0B` 這十二筆對應到我方人物；`0C` 以後全部落在下表這幾組少數幾種內容裡，多數索引共用同一列 byte：

| 索引 | 內容 |
| --- | --- |
| `0C`、`0D`、`0F`–`14`、`16`–`1A`、`1B`–`1E`、`20`–`22` | 同一列樣板：職業 `03`、LV 10、HP 960、MP 480、MV 6、AP 300、DP 100、DX 160、配備 `62`／`78`，法術遮罩空 |
| `0E` | 同上，只有職業改成 `08` |
| `15`、`1F` | 職業 `08`、LV 15、HP 640、MP 200、MV 9、AP 340、DP 280、DX 140、配備 `2D`／`69`，法術遮罩有 `06` 奔雷彈 |
| `23` | 職業 `06`、LV 1、HP 200、MV 5，其餘為 0 |
| `24`–`31` | 職業 `06`、LV 1、HP 1、MV 1，其餘為 0 |
| `32`–`3A` | `00`–`08` 的逐 byte 複本（`09`–`0B` 沒有複本） |
| `3B` | 職業 `00`、LV 16、HP 60、配備 `3F`／`99`（與 `09` 蓋亞的配備相同），其餘為 0 |

轉職型態的索引在這張表裡拿到的是那列樣板，不是該型態自己的出場屬性——轉職型態只在 `FRILEVUP.DAT` 與 `GETMGTAB.DAT` 有專屬內容。

`09` 蓋亞的遮罩是空的，攻略站列的轟神砲來自 `A4` 強化套件——那件物品的 `K1` 是 `21`，正是「習得轟神砲」。

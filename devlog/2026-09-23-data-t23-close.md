# 票 23 收尾：落地之後的查核

t23-02 跑完時連結器的清單已經空了，gate 與逐 byte 比對全綠。但那兩個判準只證明「每個符號的內容等於原版」，證明不了「沒有人漏記一個佈局依賴」——每個判定 agent 只看自己那一個符號，而佈局依賴的本質是「別人的讀寫打到我」。所以收票前另外做了一輪查核，全部是唯讀的 agent，一次一個問題。

## 先做的：全鏡像掃「落在符號內部或符號之間」的存取

一支 Ghidra script 掃過 89,420 條指令，把每個落在 `0x60000..0x70054` 的位址運算元依 232 個符號的區間分桶。符號內部的 83 筆全是同一個陣列內的索引；落在空隙的 1,048 個位址全屬 CRT／AIL 或字串常數；「常數屬於 A、目標卻在 A 外」的組合只有一組牽涉遊戲全域，查下來是 Ghidra 常數傳播把 `0xFF` 帶進了不成立的分支。結論乾淨。

但它自己講明了方法的邊界：它只抓得到「折疊成常數後落在別人身上」，抓不到「執行期索引超出表尾」——而已知的每一個佈局依賴（地形表類別 6、佇列游標、音效表 `-1`）都是後者，在指令裡只看得到一次乾淨的起點存取。所以這一掃不能當成「沒有漏」的證明，只能排除一類失誤。後面四件就是補這個盲區的。

## 四件執行期越界的查證

1. **章節事件表（50 格）會不會走出表尾。** 派發點只擋 `!= 0xFF`。把所有寫入者追到資料來源（`MAPnn.DAT` 的格子事件表、回合事件、可搜尋格、死亡腳本），掃遍出貨的 30 張章節地圖，索引最大 49，剛好用到最後一格。不需要約束。
2. **post-action 表會不會被章節編號 ≥ 30 索引。** 過場腳本的 `SWITCH_MAP` 確實把章節編號設到 0x34 這類值，這是最像會出事的一條。追下去發現回合迴圈只有一個入口，每條進入路徑都先把編號定回 0..29；每支 `ICONnn.DAT` 的最後一個 `SWITCH_MAP` 都回到 nn，戰鬥中跑的 `ICON7-x` 根本沒有這個 opcode。不需要約束。這支 agent 跑到一半撞到 session 的用量上限，接回來從頭做完。
3. **sprite 快取群組表（30 格）。** 出貨資料兩次歸零之間最多 23 個群組。不需要約束。
4. **移動網格兩個 800 byte 陣列。** 雙緩衝、每 bank 400，全部地圖與消耗列模擬下一波最多 89。不需要約束。

第 3、4 件是 code review 提出來、自己標了「可達性未證」而沒列成問題的；照專案規則收票前不能留著，所以各派一支去定案。

## 真正打中的：佇列溢寫跑得比交接說的遠

票 22 交接說「字形陣列第 204 格以後會寫到游標後面的傳送座標」。查證 agent 逐 store 讀四個生產端，發現每一次存入前都重讀游標，所以第 200 格的字形寫在游標的低 byte 上時游標立刻變成那個字形值——交接那句「線性寫到第 204 格」的前提是錯的，傳送座標在一般情況寫不到。

但同一機制給出另一條路：跨過第 200 格的若是帶前導空白（`0xFF`）的數字，游標跳成 255，之後的字形寫進 `0x643b0..0x64443`，那是一整排資源指標。這在出貨資料下可達（一次打到 51 個目標），交接的結論是對的方向、錯的範圍，t23-02 照交接只釘了四個符號。這件交給了 t23-03 重判，過程見那一篇。

這支 agent 也在用量上限那一刻被砍斷，當時正要用窮舉模擬驗證自己的手推；接回來後模擬確認可達游標集合是 {0..200} ∪ {259..400}。

## code review 抓到的文件錯

`data_emit.md` 說村莊旗標是 `gamedata.c` 最後一個帶初值的物件，所以那 3 byte 零尾端只是防模組邊界。實際上旗標後面緊接兩個初值 `0x01` 的 byte，尾端擋的是它們；照舊理由拿掉尾端，地形類別 6 的 DEF 讀取會讀出 `0x00010100`。那段文字是試跑 t23-01 之後我自己寫的，當時 `gamedata.c` 只落了 12 個符號、旗標確實是最後一個，t23-02 落地後前提就失效了，而文字沒有跟著改——典型的「結論寫在前提成立的那一刻」。

## 順帶修掉的知識庫錯誤

查第 2 件時掃遍 66 支腳本，發現 `resource_info/map.md` 說「`MAP00`–`MAP62` 共 63 組、`MAP46` 沒有腳本會切過去」與實際不符：檔案是 `MAP00`–`MAP64` 缺 30 與 33，`WIN05.DAT` 開頭就切到 `MAP46`，真正沒人切過去的是 `MAP31` 與 `MAP49`。`assets/enemies.md` 抄了同一句，一起改。

另外第 4 件的 agent 指出知識庫沒有 `.MPL` 地圖圖層格式的頁（寬高在表頭 `+7`／`+9`），它是直接讀 `src/rsrc.c` 與實際檔案量的。這不在票 23 的範圍，留著沒補。

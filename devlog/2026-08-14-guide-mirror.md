# 2026-08-14 攻略站鏡像（票 03）

## 先摸清站台長什麼樣

工作票寫的是「9 個內容頁抓下來解析成結構化資料」。開工第一件事是搞清楚那 9 頁到底在哪、長什麼樣。`index.htm` 是 frameset，WebFetch 拿不到 frame 結構（只回「本頁使用 frame」的 fallback 文字），改抓 `fdps/menu.htm` 才拿到 9 個連結：notes / trick / fdps / item / spell / list / memory / modify1 / modify2。

要找前作站台時卡了一下。目錄本身不可瀏覽，直接請求 `.../c31/fdps/fdps/` 是 404。改走 GitHub API 列 `chiuinan/chiuinan.github.io` 的 repo 內容，一次就看到 `c31/` 底下 195 個遊戲目錄，其中 `fd`、`fd2`、`fdps` 正好是一代、二代、外傳。三代的頁面命名幾乎一致，這是「以遊戲代號參數化」能成立的基礎。

抓下來第一眼以為編碼有問題：`repr()` 出來全是亂碼，開頭有 `EF BB BF`。試 big5/cp950/big5hkscs 全部解不開。實際上檔案就是 UTF-8 加 BOM，亂碼只是終端機的顯示問題——`utf-8-sig` 一次就對。這條岔路花的時間不多但值得記：Windows 繁中環境下，看到亂碼要先懷疑輸出端而不是檔案本身。

另一件當時記下的事：整站沒有任何全形空白（U+3000）。工作票寫的「`<pre>` 區塊內以全形空白對齊的等寬表格」其實是 ASCII 空白加上 CJK 字元佔兩格的顯示寬度對齊。差別很大——按字串索引切欄位一定錯位，要按顯示寬度切。

## 走進死路：寫 parser

照票面實作了完整的解析層：`textblock.py`（BOM、`<pre>` 抽取、顯示寬度切欄、以樣式標籤當區段錨點）、`parsers.py`（9 個頁面各一個解析器）、`guide_scrape.py`（fetch/parse/verify），加 24 個單元測試。三代全部跑得通，FDPS 227 件裝備、30 章攻略、modify2 四個目標 12 個 entry 都解出來了。

過程中不斷長特例：

- 欄位切分改用「所有列都空白的顯示欄位視為欄界，且至少連續 2 格」，才不會把 `距離-1 (標準=1-2)` 裡的單一空白當成欄界。
- 記憶體頁的 byte 佈局 token 一開始漏了 `-H`（以 `-` 開頭），regex 得放寬到「2～3 個字元」。
- 法術習得表的欄界不能從資料列推——有的角色只學一個法術，整片右邊都空白，推出來的欄界會跑到第 31 欄，把 `4 破龍擊` 的等級切掉。改成只從表頭那一行推欄界。
- 一代的裝備頁根本沒有物品編號，是三張以名稱為鍵、欄位完全不同的表，只能改掛通用表格解析器。
- 一代章節寫「第一章之一」，二代與外傳寫「第1章」，得加中文數字轉換與 `之N` 分段。
- 二代的 `FDSHAP.DAT` 段沒有編號條目，只有 `地形控制資料：` 這種主題行，得加第二套切分規則。
- 一代的武器表在同一張表中間畫 `----` 分隔各武器類別，原本「遇到 rule 就是新表」的邏輯會把資料列升格成表頭，改寫成狀態機才對。

每一條都能修，也都修了。但這串清單本身就是結論：**這些頁面的「格式」是假的**。作者手寫，三代排版各不相同，同一頁內也不一致。解析器只會一直長分支，而且讀錯時不會報錯，只會安靜產出錯誤的事實——比沒有結構化資料更危險。

使用者在這裡喊停，指出想要的是把原文抓下來留著、要用時字串搜尋。整個解析層刪掉，寫成 ADR-0006。

三個檔（`textblock.py`、`parsers.py`、`test_guide_scrape.py`）與 `workspace/guide_scrape/` 全部移除，只留下 `guide_scrape.py`，子命令從 fetch/parse/verify 改成 fetch/list/show/search。

## 剝標籤的一個細節

純文字版不能用空白替換標籤，也不能在標籤位置插任何字元——內容靠顯示寬度對齊，`<b>` 就地刪掉後面的字才會停在原位。只有三個例外：`<br>` 與攻略頁每章的 `<table>`（寶箱圖例）換成換行，`<img>` 換成 `[圖 檔名]`，`<head>` 整段丟掉（否則 `<title>` 會變成第一行，和頁面本身的標題重複）。

一度以為表頭和 `====` 分隔線被黏成一行，追了一下發現是 PowerShell 主控台的顯示問題，檔案本身是好的。同一個坑第二次踩。

第一版把區塊標籤（`<table>`、`<td>`、`<p>`）換成換行，再用 `\n{3,}` → `\n\n` 收掉多出來的空行。看起來沒問題，實際上把作者自己用來分隔區段的三重空行也一起壓平了——`list.htm` 有 7 處這種分段，壓完之後區段界線和一般段落間隔長得一模一樣。改成區塊標籤也就地刪掉、完全不做空行收斂，輸出反而更乾淨：`<td>` 前後本來就有換行，刪掉就是對的結果。驗證方式是數原始 HTML 與純文字裡「連續 3 個以上換行」的出現次數，兩邊都是 7。

## 忠實度抽查

前作 FD2 的知識庫是從同一個站台建起來的，等於現成的對照答案。抽查裝備 `0B`/`33`/`3D`/`A3` 與升級成長表前九名角色，鏡像與 `fd2-anatomy` 記錄的完全一致；差異只有前作轉錄時補的排版空白，以及前作訂正過站台的一處筆誤（風神弓 `DP040` → `DP 040`）。

順手做了一件票面沒要求但很有價值的事：把二代五張表的攻略站偏移減去前作知識庫記錄的模組偏移，發現差值一律是 `0x19014`，攻略站另給的第二組偏移則一律差 `−0xC200`。也就是說攻略站給的是執行檔內位置，兩組對應兩個版本的執行檔，基底各自固定。物品表在第一組差 `0x19015`，多 1 個 byte；一度想寫成「攻略站的 record 佈局開頭有 `--` 填充 byte 所以指的位置晚一格」，但這只是猜測——攻略站畫的佈局把那個 `--` 也算進去了，反而該預期兩邊一致。沒查證的因果不寫進知識庫，只記下差 1 這個事實。外傳的偏移要當基準真值用之前得先解出同樣的基底——留給票 07。

## 複審抓到的東西

跑 `/code-review` 之後修了八項，其中三項是真的：

- `fetch` 原本邊抓邊寫，第 6 頁失敗會留下 1～5 頁是新的、6～9 頁是舊的鏡像，正好是 ADR 裡宣稱「不會產生半份鏡像」的反例。改成全部抓完收在記憶體，成功才整批落地。
- 攻略頁的章節地圖只被改寫成 `[圖 檔名]`，圖片本身沒抓下來。ADR 說鏡像進版控是為了「站台消失也不影響已建立的結論」，但地圖留在站台上等於這個理由只兌現了一半。三代合計 112 張、約 12 MB，一併鏡像到同一層，原始 HTML 的相對 `src` 也因此在本地指得到。
- `spec.md` 還寫著已經作廢的設計（「輸出結構化資料」「全形對齊欄位切分」「攻略解析器先跑前作站台」），票改了但 spec 沒改，兩份文件互相矛盾。一併修正。

其餘五項是小的：`show` 的頁名沒驗證（能用 `../../../CLAUDE` 走出鏡像目錄，且對一代查 `spell` 會回「請先 fetch」而不是「一代沒有這頁」）、`list` 只在完全沒鏡像時才提示、`<img>` 的 `src` regex 只認雙引號、`chapters/_index.md` 的連結文字與 href 不一致。

## 沒做的事

`assets/` 與 `chapters/` 這一輪沒有寫入任何內容。原本規劃是從解析結果生成，解析層取消後，這些數值的正確做法是需要時從鏡像讀出來、與資料檔實際 byte 交叉驗證後再寫成正典檔——那是票 07 之後的事，不該在這張票裡靠攻略站單一來源就落地。

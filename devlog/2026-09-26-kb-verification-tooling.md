# 票 25.17 第一段：全知識庫驗證的工具與確定性的收尾項目

開發者先把範圍縮小：產生器寫出、閘門逐格比對資料的內容與已逐條驗證過的 `cut_content/` 只跑閘門，其餘人手寫的文件一份一個 agent 逐條驗證，另外加一段跨文件一致性掃描。這一段只做不需判斷的部分：兩支 workflow、它們的非判斷腳本、收尾項目裡確定性的修正。兩支 workflow 交給主 session 代跑。

## 前作沒有可沿用的工具

`fd2-anatomy` 的 `tools/kb_overhaul/` 只有章節頁的產生器與一次性的位址 rebase。前作的逐檔驗證（git log 裡 batch 7a–7f，`ad85325b`–`2bfa777e`）是主 session 親自核對每一處漂移，commit 訊息寫「主 session 逐一親核」，沒有留下 workflow 或判定格式。能沿用的只有形狀：逐檔驗證之後再做一輪跨 `_index.md` 的一致性收尾，而且前作每個資料夾都修出 5–43 處漂移，說明這一輪值得做。

## 單元怎麼切

`pitfalls.md` 有 151 KB、`vfs.md` 35 KB，一個 agent 一份文件對它們太大；但票面規定粒度是文件而不是一條事實，理由是事實的對錯要看上下文。折衷是長文件照 `##` 節切段、一段最多約 15,000 字，一段仍然只給一個 agent，agent 可以讀整份文件當上下文、只判自己那幾行。第一版上限 22,000 字切出 94 段，`pitfalls.md` 一段就有二十多列要逐列查 `src/`，改成 15,000 字、110 段。

產生區塊折成一行不給看。`data_tables` 的七張表靠表頭辨認（`data_tables.TABLES` 本來就以表頭找表），`data_skill` 逐列對照的手寫表不折，改在表前標明哪些欄已被閘門涵蓋——`characters.md` 出場屬性表裡「人物／職業」斜線後的職業名就沒有閘門，折掉會漏驗。

切段的邊界一開始是每次重算的。想到落地時的問題：第一段的修正讓那一段變長，貪婪打包會把下一節推到下一段，後面每一段的 `unit_sha1` 全變、判定全部變成過期，續跑會把已經落地的段重判一次。所以第一次跑時把切法凍結（記每段第一行的文字與它是第幾次出現），落地後再加記 `_landed_sha1`，gate 對這兩個 sha 都認。

## 跨文件一致性：先試了重複偵測

想找「同一件事寫在兩處」。第一版把每段文字（段落、列表項、表格列）切成字元 4-gram，重疊比例 ≥ 0.6 就連起來、以 union-find 分組：89 組，其中一組 82 個段落、一組 18 個。看了才知道黏在一起的是程式碼引用——幾乎每章頁的處理流程都寫 `` `fdps_roster_write_back_battle_units`（`0x23980`） ``，4-gram 大半落在函式名與位址上。改成只比文字（去掉反引號裡的東西、連結網址與標點）之後剩 5 組，其中兩組是 `battle_assets.md` 的素材連結列與 `map.md` 的統計列，真正的重複反而沒抓到。門檻降到 0.45、再要求段落至少有 30 個中文字，得 36 組，看起來多數是真的候選（例如 `pitfalls.md` 的建置兩列與 `build_pipeline.md` 幾乎逐字相同）。再排除兩種設計上就會相似的：章節頁之間各自重述自己那一章的流程，以及資料夾 `_index.md` 描述它所連結的頁面的那一列，剩 34 組。

只靠重複偵測抓不到最危險的那種：同一個錯在 A 頁被改了、B 頁寫法不同所以不像重複。所以主力放在「修正的擴散」：第一段落地的每筆事實修正，取改前那句的錨點（位址、`fdps_` 符號、檔名），把其他文件裡提到同樣錨點的行列給一個 agent 判斷有沒有同樣的錯。這要等第一段落地之後才能產生，所以一致性 workflow 必須第二個跑。另外兩個來源：驗證者順手記下的跨文件矛盾，與票面要求重判的四組 `cut_content/` 分類。

## 收尾項目

**呼叫圖總數。** 重跑 `BuildCallGraph.java`：1,345 function、3,741 條直接邊、411 條表分派邊。`architecture.md` 寫的 1,008 可達、337 走不到、「325 個指標表進入點」用四種起點定義都重現不出來：只從進入點 790／555；進入點加全部指標表目標（297 個）980／365；加「進入點本身存在 slot 裡」的 286 個 function 973／372；加沒有分派者的那 17 段表的目標 908／437。原文的六大群集（58、24、23、10、8、7）與第三種最接近（只有最後一個是 8 不是 7），`fdps` 36 在後兩種都對得上。選第三種當定義，理由是跳躍表裡指向 function 中間的 slot 是 `switch` 的標籤，把它所在的 function 當起點等於說一支沒人呼叫的 function 因為自己肚子裡有 `switch` 就算走得到——第二種定義正好因此把一支 `fdps` function 算成可達。`analyze_graph.py` 加算這一種並按快照的 `pool_*` 標籤分池。`architecture.md` 另有「75 個共用 helper」（現在是 83）與「群集全部落在 `0003c000` 以上」（走不到的 36 支 `fdps` 有一半以上在 `0x10000`–`0x3bfff`）兩處也對不上，留給逐文件驗證，不在這裡順手改。

**全域文字頁的 `0x00`。** 守衛剔除的規則 `guarded_out_values` 原本寫在 `chapter_facts.py`，但條目運算式的掃描歸 `global_text.py` 所有（`tools/_index.md` 的擁有者表），所以把規則搬過去、`chapter_facts` 改成引用，而不是在 `global_text` 再抄一份。搬的時候順手修了一個潛在錯誤：原版用 `int(x, 0)` 解數字字面值，遇到 C 的八進位寫法 `010` 會丟例外，改用同檔的 `_c_integer`。修好後 `0x00` 沒有任何讀取端，原本的表只列有讀取端的條目，這一列會直接消失；改成固定列滿前 9 條、沒有讀取端的寫「沒有讀取端」。

**`story.py`。** `NEVER_SHOWN_OVERRIDES` 的 `(16, 0x00)` 在第 16 章判定改寫後已由判定檔提供，移除。`never_shown_text` 的 `int(str(entry), 16)` 在條目是整數 13 時會讀成 `0x13`；判定格式的擁有者是 `chapter_facts.parse_entry`（接受整數或 `0xNN` 字串，其他一律報錯），改成用它。

**過場地圖是否每張都有腳本載入。** 25.11 的普查把地圖 32 以後一律當到得了。查證：有 `MAPnn.DAT` 的地圖 32–64 除了 49 每張都有腳本 `SWITCH_MAP` 過去，66 支腳本每支都有呼叫端，地圖 33 沒有 `MAP33.DAT`。假設成立，寫進 U10。

**cut_content 的三處引用位址。** 全知識庫的確定性檢查在 `cut_content/` 抓到五處 `` `名稱`（`位址`） `` 寫的是 function 內部的指令位址。四處只是寫法，改成「`名稱` 內的 `位址`」；`items.md` 那一處的 `0x26dec` 根本不在 `fdps_run_death_scripts` 裡，是 `fdps_apply_item_effect_to_targets` 呼叫它的地方，照實改寫。

## 審查之後改掉的

照 implement 流程做了兩軸審查（標準與票面），改了這些：

- 第一版兩支 workflow 只判定、落地交給票的 session 手動跑——照 25.14 重驗 workflow 的前例。審查指出 ADR-0007 要求腳本自己落地並在落地後跑閘門，前例本身就是偏離。改成最後一段由不做判斷的 agent 跑 `apply` 與全部閘門，閘門不過只回報、不自行修；另一張票正在改的頁用 `exclude` 擋下，之後再跑一次 `apply` 補上。
- `apply` 原本對「沒有判定、判定不過 gate、還沒回掃」的項目直接 `continue`，這正是 ADR-0007 5.3 說的吞掉。改成每一項都以名字列進拒收清單，結束碼只放過 `exclude` 擋下的。
- 回掃的 agent 若把判定檔弄壞，原本直接記未完成；補上 5.1 的重試一次。
- 分類重判原本把 C16c–e 三條交給同一個 agent、`30:0x13` 與 `0x14` 也放在一起，違反一個 agent 一項，拆成一個條目一項。
- 擴散項目原本跳過修正所在的整份文件，長文件別段裡的同一個錯就永遠不會成為候選；改成只跳過修正後那幾行。驗證者回報的矛盾若兩邊的驗證者都記了，原本會變成兩個 agent 各改一次，改成同一對頁面、同一錨點合併成一項。
- 驗證者提出的踩雷點候選原本只進收尾報告，沒有人落地；改成一致性段的一種項目，一條一個 agent 判斷夠不夠格、`pitfalls.md` 有沒有收過。
- 腳本對 agent 顯示的說明原本是中文，改成英文（CLAUDE.md 的語言規範）；表頭等遊戲資料照原文。`split_row` 原本抄了一份 `data_tables` 的，改成 import 擁有者。
- `architecture.md` 那句「群集全部落在 `0003c000` 以上」接在新改的六大群集表後面，其實只對這六個成立，順手改成「這六個群集」；「75 個共用 helper」仍留給逐文件驗證。

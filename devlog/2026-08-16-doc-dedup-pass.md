# 2026-08-16 規範文件去重：spec、ADR、CLAUDE.md

把 `.scratch/fdps-rebuild/spec.md`、`docs/adr/` 全部七篇、`CLAUDE.md` 三邊對讀一次，找同一件事被寫在幾個地方、以及寫錯地方的內容。

## 先找出誰是誰的副本

三份文件的職責本來是清楚的：CLAUDE.md 是每回合都載入的工作規範，ADR 是決策的理由與取捨，spec 是問題、方案、範圍與工作票的來源。實際讀下來，複製的方向幾乎都是「往上游抄」——ADR 寫了理由，CLAUDE.md 抄一份規則，spec 再抄一份摘要。

最嚴重的是 ADR-0007 的五條必要條件。CLAUDE.md 把五條連同 5.x 的細節整段複述，spec 又用一個 bullet 摘要一次。三份都在講同一件事，而只有 ADR-0007 會被更新——CLAUDE.md 那份的「上面四條」在 ADR 補到五條之後就沒跟上（ADR-0007 內文自己也有一處還寫著「上面四條」，一併修掉）。

ADR-0007 自己也有內部重複：「不抽共用骨架」在 Considered Options、Decision、Consequences 講了三次，「walk_ticket12 是參考範例而非框架」講了兩次。

## spec 的「已確立的事實」是過期的知識庫副本

這段本來的用意是讓開工的 agent 知道哪些不用重新求證。問題是知識庫建起來之後它沒有跟著更新，現在三條與正典牴觸：

- CD 音源寫「音樂可能根本不由主程式播放」，而 `program_info/cd_audio.md` 已經判定選曲、起播、停止、循環全由 `FDPS.LE` 自己下命令，必須連同重建。方向剛好相反。
- SAF 寫「待逆向」，`resource_info/saf.md` 早就完整了。
- 編譯器小版本寫「只靠兩個浮點函式符號」，`rebuild_info/build_flags.md` 現在有四項獨立證據。

function 數更亂：spec 內部同時存在 719（Problem Statement）與 1,042（規模參考），而 `program_info/code_pools.md` 是 1,347。一份文件裡兩個互相打架的快取，兩個都不對。

這種錯法比沒寫還糟——它看起來像已經查證過的結論，會讓人不去翻正典。所以整段改成指向各正典檔，不留數值。

## 沒有擁有者的兩條事實

原本想把「已確立的事實」整段清空，清到一半發現有兩條在知識庫裡根本沒有落點：存檔編解碼與前作同構、執行檔內不含中文字串。`grep` 過 `program_info/`、`resource_info/`、`assets/` 都沒有。

想過就地塞進 `program_info/architecture.md` 的「尚未確定的事」，但那節是留給未定案的問題，這兩條是已經驗證過的結論，放進去等於把它們標記成待辦。也想過「執行檔內無中文字串」寫進 `pitfalls.md`，但 pitfalls 收的是「重建時照直覺寫會偏離原版」，這條是分析手法上的提醒，不合收錄門檻。

最後決定留在 spec 但明寫「知識庫尚無正典擁有者」，不假裝它們已經歸位。硬塞一個不對的擁有者，之後找的人會找不到。

## 其他

CLAUDE.md 的攻略站條目還留著 frameset 入口 URL 與「直接請求目錄會 404」的抓站細節。鏡像已經落地、`guide_scrape.py` 的 `fetch` 也把 URL 組法寫進 `GAMES` 表了，這些細節只剩下引誘人去連線抓站的作用，刪掉改成「用 `search`，不要直接抓站」。

同一份還留著「README 尚未建立時，讀 fd2-playbook」的分支，README 早就在了。

`README.md` 也複述了 ADR-0005 的匯出時機與 ADR-0003 的驗證分層，這次沒動——它是入口文件，做摘要有理由，但長度已經接近再講一次，之後要留意。

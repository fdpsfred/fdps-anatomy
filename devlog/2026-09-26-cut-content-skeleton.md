# 票 25.10：`cut_content/` 骨架與程式痕跡

這一段要讓知識庫多出「刪減與未用」這個視角：新頂層資料夾、分類規則、總表、素材的放法，外加第一份主題檔 `code.md`（程式痕跡）。25.11–25.14 會在我之後平行開工，所以骨架得先 commit，後面才轉錄內容。

## 先查前作

`fd2-anatomy` 沒有刪減與未用的資料夾。`tools/rsrc_unresolved` 是 FDOTHER 死 index 的一次性驗證，`tools/kb_overhaul` 是章節表產生器，都不是可以沿用的形狀。所以骨架是自己設計的；素材的解碼一律接本專案既有的擁有者（`cel_decode`、`saf_decode`、`vfs_dump`），`tools/cut_content` 本身不寫解碼器。

## 骨架怎麼定的

幾個考慮過又放棄的方向：

- **先建四個空的主題檔**（`units.md` 等），好讓連結不斷。放棄，因為空檔案裡只能放「待某票填入」這種流程字眼，知識庫不該有。`_index.md` 的主題表對還不存在的檔只寫檔名、不加連結，各票建檔時再改成連結。
- **排除清單也由程式產生。** 放棄。總表由 `cut_content.py index` 從各主題檔的標題列與 `分類：` 行產生，但排除項沒有主題檔條目（票面規定排除只列在 `_index.md`），硬要產生就得多發明一種來源格式。排除清單改成依主題分小節、由各票手寫自己那一節，`check` 只驗證編號不與條目重複。這樣也順便解掉平行寫入的衝突：每張票只動自己那一節，總表則是可重產的。
- **素材放 `cut_content/assets/`。** 名字會和頂層的 `assets/` 混淆，改成 `media/<主題>/`。CD 音軌的 WAV 要從光碟映像重生、不進版控，但知識庫又不能引用 `workspace/`，所以輸出目錄放在 `cut_content/media/cdda/`，再列進 `.gitignore`。

條目格式只固定兩行（標題列 `### <編號> <一句話>` 與下一行的 `分類：`），其餘自由。這兩行是我們自己定的結構，不是對人寫內容做 parser。

## 平行 commit 的坑

開工時共用的 index 裡已經有 25.8 暫存的檔（`tools/_index.md` 等）。照一般的 `git add` 加 `git commit`，會把別人暫存的東西一起帶進我的 commit。改成在暫存資料夾開一份臨時 index（`GIT_INDEX_FILE`）：以 HEAD 為底，放進我擁有的檔，共用檔則放「HEAD 版本 + 我那幾行」，接著 `write-tree`、`commit-tree`、`update-ref`（帶舊 HEAD 當條件）。最後把同樣的幾行補進共用 index 與工作目錄，免得別人下一次 commit 把我的行當成刪除。三個 commit 都這樣做，別人暫存與未暫存的改動都沒被碰到。

中途也看到 `cut_content/_index.md` 與 `tools/cut_content/cut_content.py` 被 25.11／25.13 改了（加 U 條目、註冊素材產生器），這兩個檔之後的 commit 也改用「HEAD + 我的修改」的方式組。

## 轉錄 25.9 的 C 系列

16 條裡 7 條成立、9 條需修正。轉錄時以判定檔的 `corrected_claim` 與 `conclusion` 為準，不採清單原文。C12、C14、C16 是排除，進 `_index.md` 的排除清單；C16 本身是一張清單，拆成 C16a–h 八個子項。DPMI 那六支被 Miles AIL 呼叫，是在用的功能，不算排除也不算痕跡，只在排除清單下方用一句話說明。

寫的時候刻意不寫行號：判定檔的證據全是 `src/x.c:NNN`，但 25.15 正在改 `src/` 的註解，行號一漂移，知識庫就錯。條目只寫檔名、function 名稱與 Ghidra 位址。

`resource_info/save.md` 原本說第 4 個 slot 是「空殼」，與 C8 判成前作遺留矛盾，就順手改掉了。`CONTEXT.md` 的 Slot 詞條也寫空殼，詞彙表不歸我改，先回報上去。後來開發者自己改了。

## 分類邊界：開發者定了兩條規則

25.9 留下 C2、C6、C8、C11 的分類疑義，我先照判定歸類並在條目裡寫明理由，回報時提出要補兩條規則。開發者決定（`CONTEXT.md`）：

1. 遊戲自己的模組裡做好卻沒被呼叫的成員歸殘留內容，只有第三方程式庫（Watcom CRT、Miles AIL）沒用到的 API 才排除。
2. 從 FD2 繼承、FDPS 改寫過卻沒啟用的歸殘留內容，原封不動繼承的才是前作遺留。

C2、C6、C11 因此定案為殘留內容，C8 維持前作遺留，條目裡「分類待決」的說明全部拿掉。

不過規則一旦寫下，就不只影響這四條。照字面套：

- C16c（MSCDEX 存取層沒用到的 19 支）、C16d（VFS 讀取器的 3 支）、C16e（RLE 繪製走不到的 6 種模式）都在 fdps pool 裡，是開發商自己的模組，不是 Watcom 或 Miles。規則一明講這不算通用程式庫，所以從排除清單搬進 `code.md`，成為殘留內容。
- C10 的判定原本說「殘留內容的前提是有做好的內容，而 FDPS 沒有這種封裝檔」。判定裡也寫了它的介面與錯誤處理跟 FD2 不同，我一度照規則二把它改成殘留內容。審查時 spec 讀者指出，判定的待決問題明寫改寫可能「在中間某個作品就已完成」：映像只證明它在 FD2 之後被改過，沒有證明是 FDPS 改的，規則二的前提並不成立。已改回前作遺留，條目裡寫明理由。這是套規則時自己造的死路：把「跟 FD2 不同」直接讀成「FDPS 改過」。

C16c–e 的事實都已經過 25.9 驗證，換的只是規則的套用，所以直接照做，並在回報裡點名給開發者確認。C16e 另外對照了 FD2 的繪製器（`fd2-anatomy/program_info/gfx.md`）：FD2 是一支 RLE 解碼器加三種調色盤模式，另有一支重映射函式，沒有 13 個 kernel 的 dispatcher，所以不是原封不動的前作程式。C5 沒動：被留下來的是 FD2 原樣的全域與兩處讀取，FDPS 改寫的是旁邊的機制（改用區域變數），遺骸本身沒被改寫。C3 的平手門檻 FD2 是 `0xB`、FDPS 是 `0x12`，那只是跟著法術表換了編號，也沒動。`program_info/architecture.md` 的工作副本有一張「呼叫圖走不到的部分」表，仍把 MSCDEX／VFS 寫成「通用程式庫沒用到的成員」、把讀取器寫成前作遺留；那不是我的改動也還沒 commit，交出去由擁有者對齊。

## 新痕跡 workflow

25.9 的收尾報告裡，給 25.10 的新痕跡有 23 條。寫了 `tools/cut_traces/`：一條一個 agent，驗證真假並決定落點；會落地的、判定不是成立的、信心不是 high 的，都交給第二位讀者。本機沒有 JS 引擎，語法只能用一支自寫的括號與模板字串平衡檢查器過一遍，並拿 25.9 的腳本當對照組。主 session 代跑的結果：23 條全數完成、沒有停止；落點是已收錄 10、補充 4、轉交 7、捨棄 2，沒有新條目也沒有排除；回掃 11 條，改寫 2 條。

兩條改寫與另一條轉交，揭露了我自己轉錄的 `code.md` 有錯，是這段最值得記的死路：

- **C8「唯一碰它的程式」**（T10-13）：我照 25.9 的判定寫「整份映像裡唯一碰第 4 格的程式是戰鬥選單存檔」。第一位讀者看出這句要限定成「以 slot 欄位定址」，卻判成已收錄。第二位讀者指出，存讀檔畫面的章節存檔在 `FDE.SAV` 不存在時會以 `memset` 把整份映像連同第 4 格填成 `0xFF`（`0x242dc`），所以 C8 那句本身就是錯的。25.9 的 C8 判定也只查了以 `+0x59a3` 定址的指令，整塊 memset 不會出現在那種搜尋裡。已改正。
- **C13「沒有任何按鍵序列的比對」**（T10-18）：同一頁的 C1 就在講神秘商店的暗號，那正是逐鍵比對掃描碼的序列。25.9 的 C13 判定只找作弊碼式的序列比對，沒把設計好的暗號算進來；我轉錄時也沒把兩條對起來看。已改成「除了神秘商店暗號之外沒有」，按鍵清單也補上暗號用到的鍵。
- **T10-02**：第一位讀者把 Ghidra 的連結位址 `0x3c6f7`、`0x30ca4` 當成堆疊上的實際值，推出暗號列第 2、3 byte 是 `03 00`。第二位讀者指出 DOS/4GW 會把物件搬到 1 MB 以上，只有最低 byte 確定。C1 的補充照第二位的版本寫。

補充落地到 C1（T10-02）、C6（T10-10，style 6 以 height 錨定的原版錯誤；C6 原本說「完整可運作」，改成「做好的」）、C9（T10-15，`SETSOUND.EXE` 與 `AILDRVR.LST`）、C15（T10-20，字串池填充空隙的殘渣）。T10-01（暗號比對位置不歸 0）寫進 `pitfalls.md`。轉交 25.14 的 3 條都是 MAP31／MAP49（地圖 31 的 11 筆多出來的部署記錄，重複報了兩次；另一條是兩張沒有路徑的地圖）；轉交 25.15 的是 `src/aiscore.c` 的位址註解、C8 與 C13（已在本票自己改掉）、Ghidra 快照的 10 個字串起點。

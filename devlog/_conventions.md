# devlog 寫作規範

本檔是 devlog 寫作規範的唯一正典，`CLAUDE.md` 只留核心三條與指向這裡的入口。規範要改就改這裡。

devlog 記錄「怎麼走到這個結論」，知識庫記錄「結論是什麼」。兩者嚴格分離：任何在 devlog 裡確立的事實，結論要另外寫進知識庫；知識庫裡不出現分析過程。

## 檔名與粒度

`YYYY-MM-DD-<主題>.md`，一個工作段落一篇。同一天有多個獨立工作段落就開多篇，主題用短的英文 kebab-case。

不需要索引，不需要去重。重複記錄同一件事不是問題，漏記才是。

## 內容

敘事體，明確允許流水帳。要寫的是：

- 試了什麼、順序為何
- 什麼失敗了、失敗的具體症狀
- 為什麼放棄某個方向
- 當時的判斷依據是什麼，包含後來被推翻的判斷

**重點記死路。** 成功的路徑會沉澱進知識庫與程式碼，失敗的路徑是唯一會遺失的資訊。一個試了兩小時最後不通的方向，價值比一段成功的操作記錄高。

詳細程度的標準：三個月後回來看，能不能重建當時的判斷。

## `runs/`

Workflow 每次跑完的 agent 回報 JSON 歸檔到 `devlog/runs/`，與人寫的敘事分開。檔名帶日期與 workflow 名稱。這些是機器產出的原始記錄，不整理、不摘要。

# 實機驗證 — 重建版取代原版之後怎麼驗、偏差怎麼定位

重建版的整合行為由人在 DOSBox-X 裡實際遊玩確認，不建自動化對拍設施（[ADR-0003](../docs/adr/0003-manual-playtest-over-automated-golden.md)）。本檔回答三件事：兩版怎麼擺才能公平比較、誰判斷什麼、看到偏差之後怎麼走到一支具體的 function。

遊戲本體怎麼建置由 [`build_pipeline.md`](build_pipeline.md) 擁有，它的回歸閘由 [`build_gate.md`](build_gate.md) 擁有。腳本在 [`tools/game_build/`](../tools/game_build/_index.md)。

## 分工

| 誰 | 做什麼 |
| --- | --- |
| 開發者 | 實際遊玩兩版；判斷畫面、音效、時序、操作手感是否一致；逐項確認 emit 疑慮總掃交接過來的實機檢查（見票 24） |
| AI | 建置與連結；開機煙霧測試（能不能開機、進得了遊戲、有沒有保護模式故障）；開發者回報偏差之後的定位、反組譯比對與修正 |

**畫面與行為的比對不交給截圖。** 自動按鍵的落點取決於遊戲當下是否在等鍵，而兩版的執行速度不同（重建版的遊戲段不是原版旗標編的，見 [`build_flags.md`](build_flags.md)），同一串定時按鍵在劇情後段就會落在不同的畫面上，截圖分岔分不出是時序還是真差異。自動化只回答開機那一段。

## 兩版並排的條件

兩版必須只差被測的那個檔，其餘一律相同：

| 項目 | 設定 |
| --- | --- |
| 執行檔 | 原版是出貨的 `FDPS.EXE`；重建版是 `FDE.EXE` 改名成 `FDPS.EXE` |
| 遊戲檔 | 出貨的全部檔案，同一份來源 |
| DOS 延伸器 | 遊戲附的 `DOS4GW.EXE`（1.97），兩版共用 |
| 調色盤快取 | 不帶（`FMER1.TMP`、`FMER2.TMP`、`MER1.TMP`、`MER2.TMP`）。遊戲在 `FMer1.tmp` 不存在時自己建，帶著舊的會讓重建版永遠不跑建表那段 |
| 光碟 | 映像掛在 `E:`，因為 `Disk.No` 寫的是 `CDROM at e:` |
| 音效 | SB16，`BLASTER` 與 `[sblaster]` 的 IRQ／DMA 一致（[`ail_link.md`](ail_link.md)）；「無音效」那一輪把音效卡整張拿掉（`sbtype=none`），`AIL_install_DIG_INI` 因而失敗、走沒有驅動的路徑 |
| 模擬器 | 同一份 conf：記憶體 32 MB、`pentium_mmx`、`cycles=max`，不加 `-silent`（它連 SB16 一起關掉，[`pitfalls.md`](pitfalls.md)） |

## 存檔相容

`FDE.SAV` 是兩版之間唯一需要雙向相容的檔。驗法是交換：在一版存檔、把 `FDE.SAV` 搬到另一版的目錄讀檔續玩，兩個方向各一次。同一份存檔也是比較兩版行為的起點——要重現一段劇情或一場戰鬥，就從同一份存檔在兩版各玩一次。

## 從當機到 function

DOS/4GW 1.97 當機時在文字畫面上印一段傾印，位址出現兩次，只有一個能用：

| 傾印裡的 | 是什麼 | 能不能換回 function |
| --- | --- | --- |
| `CS:IP 160:001A002A` | DOS/4GW 把映像搬到 1 MB 以上之後的線性位址 | 不能。實測一支連結在物件 1 = `0x10000` 的程式執行時 `main` 在 `0x1a0040`，而且各物件不是以同一個差值搬移，沒有固定的基底能換回去 |
| `Crash address (unrelocated) = 1:0000002A` | 物件編號：物件內偏移，連結器自己的座標 | 能。這正是 wlink map 寫位址的方式（`0001:0000002a`） |

換算靠兩件事，兩件都是精確的而不是估計：

1. **重建版的 map** 列出每個公開符號的物件：偏移與它來自哪個目的檔，所以「位址落在哪支 function、屬於哪個 `.c`」是查表。
2. **C 名稱就是 Ghidra 名稱**（[`naming.md`](naming.md)），所以同一個名字在 Ghidra 快照裡的位址就是原版的同一支 function。

**跨兩個映像的只有名字，不是 function 內的偏移。** 兩邊的 body 用不同旗標編，重建版 `+0x1a` 的指令在原版不在 `+0x1a`；定位到 function 之後，要在那支 function 內對照 assembly。

修正之後跑完整的 build gate 並推進 `game` 目標的基準值，規則見 [`build_gate.md`](build_gate.md)。

不當機的偏差（數值錯、畫面錯、卡住）沒有位址可查，從現象對應的子系統找起：[`code_layout.md`](code_layout.md) 的檔案表把子系統對到 `.c`，[`emit_pipeline.md`](emit_pipeline.md) 的八類隱性契約是這類偏差最常見的根因，逐類排除。

## 已經確認到什麼程度

無人值守的開機煙霧測試，兩版在同一套設定下各跑一次：

| 項目 | 結果 |
| --- | --- |
| 連結 | `src/` 全部的 C 與組語 unit，加 AIL 與三個 CRT 程式庫；零錯誤、零警告、零未解符號 |
| 資料與組語 | 全域資料逐 byte 與原版一致、佈局約束全部成立，RLE 組語的指令序列與原版一致——都是在**遊戲映像**上驗的，不只是在單元測試映像上 |
| 開機 | 通過光碟檢查、音效初始化、全域資源載入、建調色盤快取，進入開場 logo 與標題畫面 |
| 進入遊戲 | 標題畫面按 Enter 兩次進到第 1 章開場對話 |
| 與原版比較 | 同一時間點的截圖逐像素相同，只差對話框角落等待按鍵的小動畫相位 |
| 無音效卡 | 同上的流程與結果 |

之後的一切——完整遊玩流程、交接下來的實機檢查、存檔雙向相容——由開發者實際遊玩確認。

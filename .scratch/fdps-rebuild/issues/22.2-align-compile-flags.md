# 22.2 — 重建版的編譯旗標與 translation unit 邊界完全對齊原版

**What to build:** 重建版的遊戲段改用原版真正的旗標組 `-s -ot -oe=25 -d2`，CD 模組改用原版的 `-os`，而且 `src/` 的檔案分組改成與原版的 translation unit 邊界一致，讓 `-oe` 只在原版展開過的地方展開。做完這張票，重建版的機械碼在編譯器層面與原版同源，拿 `.OBJ` 逐 byte 對照原版成為常規檢查而不是特例。

## 為什麼

票 22 收尾時查清了兩件事（旗標的量測與正典改寫在票 22 內完成，見 `rebuild_info/build_flags.md`；量測腳本在 `tools/build_flags/` 的 `oe_probes.py`、`fn_match.py`、`fn_variants.py`、`oe_threshold.py`）：

- **原版遊戲段的旗標是 `-bt=dos4g -mf -4s -fpi -s -ot -oe=25 -d2`，不是 `-od`。** 用真實 `src/` 檔逐 function 對照原版 byte，`-od` 42 支只有 6 支完全相同，`-oe -d2` 有 17 支，前者對上的在後者下全部也對上；引數推送形式 2,587 處全部對上。
- **原始碼沒有用 `_inline`。** Watcom 10.0a 的 C 編譯器不認 `_inline`／`__inline`／`inline`（E1009）。映像裡那些展開是 `-oe` 自動做的，而 `-oe` 只在同一個 translation unit 內展開。

ADR-0001 只要求功能等價，所以這不是等價性缺口。使用者仍決定完全對齊（2026-09-22），理由是：時序敏感的迴圈（契約 D）與原版同源最安全，而且之後每一次「編譯器是不是真的那樣做」都能直接拿 `.OBJ` 對照，不必另外用別的旗標重編。CD 模組一併對齊，原本「明文不帶 probe」的決定由這張票取代。

## 要做的

1. **找出原版的 translation unit 邊界。** 證據有幾條，彼此獨立：`-oe` 的展開只發生在同一個 unit 內（每個展開處與它的 callee 必在同一 unit）；CD 模組的 `__CHK` 邊界；每個 unit 的 `CONST`／`_DATA` 字串與常數在映像裡成段連續、順序跟著 unit；function 在 image 裡的連續性。每支 function 歸哪個 unit 是逐項判定，一次一支、用 workflow 跑（CLAUDE.md 鐵則），規則與證據寫進 `rebuild_info/code_layout.md`。
2. **`src/` 改照 unit 分組。** `code_layout.md` 的分組依據與行數預算要重新定：unit 邊界是硬約束，行數預算只能在 unit 內部用 `#include` 片段之類不改變 unit 的方式處理，或明文放寬。`build_routing.py` 與 `routing.json` 跟著改。
3. **`build_emit.py` 吃 per-unit 旗標**：CD 那個 unit `-os`，其餘 `-oe=25 -d2`。`build_pipeline.md` 跟著改（`verify_flags.py` 的預設已在票 22 換成新旗標組）。
4. **展開處改回呼叫。** 原版展開過的地方，`src/` 目前是手寫的開碼算式；改成呼叫同 unit 的 callee，讓 `-oe` 重現展開。`src/` 註解裡「原始碼用 `_inline`」「改成呼叫會多一條 CALL」的說法一併更正（`src/movegrid.c`、`saf.c`、`spell.c`、`sprite.c`、`statunit.c`、`palette.c`、`tests/table.c` 等）。`-oe` 不展開的位置要保持呼叫：`&&`／`||` 右側；一個運算式裡有兩個呼叫時右邊那個。`0002b034`／`0002b04a`／`0002b060` 三個 `fdps_get_rgb_*` 為什麼全部是真的 `CALL`，現有規則還解釋不了，做全映像對照時要查出來。
5. **逐 function 對照原版 byte**：`tools/build_flags/fn_match.py` 已經做得到（遮掉 LE 重定位欄位與 `E8` 呼叫目標），擴充成跑全部 514 支，結果當本票的量測；不相同的逐支說明是原始碼層面的哪一種差異（宣告順序決定的槽位順序、開碼留下的未用區域變數等）。
6. build gate 全綠。

## 已知的邊界

- `-oe=24`～`26` 結果相同，27 以上會多展開原版沒展開的呼叫。
- `-d2` 之下區域變數的堆疊槽位順序跟著宣告順序，所以宣告順序會影響 byte 對照結果，但不影響行為。
- `-d2` 只影響目的檔的除錯資訊與 codegen；連結時不帶 `DEBUG` 指令，執行檔不含除錯資訊（原版也沒有 wlink 的 `0x8386` 除錯尾碼）。

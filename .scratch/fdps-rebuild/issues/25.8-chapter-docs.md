**What to build:** 每一章都有一份文件，只看它就能知道這一章發生什麼、有什麼敵人與寶物、怎麼贏、事件怎麼跑、每一句對白。

30 份 `chNN.md`，每份涵蓋：

- 劇情概要；加入角色與加入條件（`src/chinit*`／`chend*`、攻略站）
- 敵人配置：單位、等級、數量、AI 行為、登場波次（`MAPnn.DAT` 部署記錄 × `ENEMYDAT.DAT`，名稱取 `FDETXT00`）；友軍 NPC

- 商店：道具／武器／秘密三家（`SHOPnn.DAT`）
- 特殊機制與勝敗條件（`src/chpost*`、`src/chevt*`）
- 處理流程：init／end／post／event 各函式的位址與步驟
- 回合事件與格子事件表（`MAPnn.DAT` `+0x03`／`+0x33`）
- 過場腳本逐步內容（開場與勝利，由 25.2 的解碼器產生）
- 完整對話轉錄（`FDETXTnn.TXT` 逐頁，由 25.1 的解碼器產生，標出說話者頭像、換行、換頁）

拿不到的寶物、不出場的敵兵、沒接上的對白只寫一行並連到 `cut_content/`。

- 額外場景地圖（地圖編號 31 以後）的歸屬章節與切換來源腳本

## 前作參照

- 頁面涵蓋面與節次：`fd2-anatomy/chapters/chapter_NN.md`、`fd2-anatomy/chapters/_index.md`（handler 總表、跨章機制鏈、章號與資源對照這三塊沿用為 `_index.md` 的骨架）。
- `fd2-anatomy/tools/kb_overhaul/gen_ch_encounters.py`、`gen_ch_shops.py` 解的是 `FDFIELD.DAT` 與寫死在 EXE 裡的商店表，FDPS 的格式不同（`MAPnn.DAT`、`SHOPnn.DAT`、66 個 `FDETXTnn`、過場腳本），不沿用程式，只沿用「部署按單位與等級彙總、寶物分地圖與掉落」的呈現。

## 做法

- 頁面 = agent 寫的敘述 + `chapter_facts.py` 產生的七個區塊（標頭、部署、寶物、村莊、事件、過場腳本、對話全文與讀取端），區塊夾在標記之間，落地頁可隨時重產比對。
- 資料判斷不了的三件事（非 0 波次會不會部署、掃描找不到讀取端的文字條目由誰顯示、永遠不顯示的條目）由逐章 agent 寫進 meta，落地時存進 `tools/chapter_docs/judgements/`。
- 商店與加入只連到 `assets/shops.md`、`assets/characters.md#加入`，不重列。
- `SHOPnn` 與城鎮文字：村莊載入 `SHOP` + 章節索引與 `FDETXT` + 章節索引 + 1，所以第 n 章之前的村莊用 `SHOP(n−1)` 與第 n 章自己的文字區塊 `0x04`–`0x08`；村莊一節放在第 n 章頁。

# 25 — 知識庫翻新與事實驗證

**What to build:** 知識庫的每一條結論都被對照實際情況驗證過。前作的教訓是知識庫會漂移——大量產出之後必然累積事實錯誤，寫過不等於寫對。

**執行方式：** 逐條驗證的部分依 [ADR-0007](../../../docs/adr/0007-workflow-automation-and-agent-context.md) 由 workflow 跑完，每次 agent 呼叫只帶**一份知識庫文件**，agent 把逐條驗證結果寫成檔案、只回傳「幾條通過、幾條有問題」的摘要。修正是獨立的轉錄階段——驗證的 agent 不改文件，避免「自己驗自己改」把錯誤合理化掉。

粒度取一份文件而非一條事實，因為一條事實的對錯往往要看它在文件裡的上下文；但一個 agent 仍只處理一份文件，不得拿到文件清單自行分配。

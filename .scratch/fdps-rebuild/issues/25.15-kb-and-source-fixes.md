# 25.15 — 知識庫與原始碼的錯誤修正

**What to build:** 刪減調查順帶發現的既有錯誤全部修正，知識庫、`src/` 註解與 Ghidra 三者說法一致。

逐條修正前先重新確認一次，確認不成立的就不改並在 devlog 記下：

1. `program_info/architecture.md`「呼叫圖走不到的部分」說走不到的 36 支 `fdps` function「多半由 `.object2` 的章節分派表指到」。調查結果是這 36 支沒有一支在分派表裡——四張表的 140 項在 `src/chapter.c` 全部是具名初值、有引用。重寫這一段，說明 36 支實際是什麼（`-oe` 展開後保留本體、通用程式庫、前作遺留、刪減痕跡），刪減痕跡連到 `cut_content/`
2. `src/main.c` 的註解說 `FMer*.tmp` 那組混色表寫出後沒有程式讀回；實際上 `src/combat.c`、`src/cmbspell.c`、`src/church.c`、`src/ending.c` 各有一處讀回
3. `src/icon.c` 的 `SCRIPT_OP_DEBUG_LEVEL_UNIT_3` 與它的註解把 opcode `0x61` 說成除錯用；它由 `WINGA26.DAT`（第 27 章隱藏路線）正式使用，是法蓮娜重新入隊的經驗補償。改成反映用途的名字與註解；Ghidra 若有同樣說法的 plate comment 一併改
4. `assets/items.md` 的物品名照攻略站寫，三處與遊戲內文字不同：`50` 是「火神砲」、`CC` 名稱空白、`D5` 是「空之寶石」。以遊戲內文字（25.1 的解碼）為準，攻略站寫法記成差異
5. `assets/characters.md` 把 `FRIAPRDA` 一批逐 byte 相同的列稱為「樣板」；調查認為那就是 NPC 索爾（`0C`）的出場資料（攻略站第 26 章索爾 AP 740 = 300 + 40×1 + 炎龍劍 400）。同時核對 `0D` 是否真的屬於同一組，以及 `15`／`1F` 的歸屬
6. `src/icon.c`（`SCRIPT_ARCHIVE_NAME` 與 `fdps_icon_script_run` 的註解）與 `src/icon.h` 說 `fdps_icon_script_run` 有 67 個呼叫點；Ghidra 對 `0x21650` 的 xref 是 66，`src/` 的呼叫也是 66（每支腳本恰好一個，25.2 的 `tools/cutscene_script` 掃出來的），改正數字；Ghidra 的 plate comment 若有同樣說法一併改

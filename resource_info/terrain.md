# 地圖圖層：`M%02d.DTL`、`M%02d%d.MPL`、`ATTR%02d%d.DAT`、`DSC%02d.DAT`

一張地圖（[`CONTEXT.md`](../CONTEXT.md) 的「地圖編號」）由一層事件碼層加上一到兩層場景圖層組成。每個場景圖層是三個檔：圖磚編號表 `MPL`、圖磚表 `CEL`（格式見 [`cel.md`](cel.md)）、圖磚屬性表 `ATTR`，全部圖層由描述檔 `DSC` 統一描述。同一張地圖的部署與事件腳本 `MAPnn.DAT`／`MAPnn.COD` 見 [`map.md`](map.md)。

本檔擁有這四種檔的佈局、程式的讀法，以及「任一格是什麼地形、能不能搜尋、帶什麼事件碼」的判讀程序。事件碼指到的表（格子事件、可搜尋格記錄、重繪旗標）的語意在 [`map.md`](map.md)。

## 組成與載入

`fdps_field_load_chapter_resources`（`000227e0`，`src/rsrc.c`）每次進入一張地圖時整組釋放重載，檔名的數字一律是地圖編號（`fdetxt` 例外，見 [`text.md`](text.md)）：

| 檔名 | 容器 | 載入到 |
| --- | --- | --- |
| `M%02d.dtl` | `FIELD1.VFS` | 事件碼層 `data_fdps_map_cell_event_code_layer_ptr` |
| `dsc%02d.dat` | `FIELD2.VFS` | 讀完即釋放，欄位抄進六組 `data_fdps_scene_layer_*` 陣列 |
| `m%02d%d.mpl` | `FIELD1.VFS` | 第 n 層的圖磚編號表 |
| `m%02d%d.cel` | `FIELD1.VFS` | 第 n 層的圖磚表 |
| `attr%02d%d.dat` | `FIELD2.VFS` | 第 n 層的屬性表 |

後三個對 `DSC` 宣告的每一層各載一次。任何一個成員不存在，`fdps_vfs_load_entry` 會直接結束程式——沒有「缺檔就略過」的路徑。

實際存在的檔：

| 種類 | 地圖編號 |
| --- | --- |
| `DTL` | 0–64，缺 30 |
| 第 0 層的 `MPL`／`CEL`／`ATTR` | 與 `DTL` 相同的 64 張 |
| 第 1 層的 `MPL`／`CEL`／`ATTR` | 05、07、29、63 |
| `DSC` | 0–64，缺 30、31、33 |

由此得出兩件事：

- **地圖 31 與 33 載入不了。** 兩者都沒有 `DSC`，載入常式讀它時就結束程式；33 另外連 `MAP33.DAT`／`MAP33.COD` 都沒有。它們的圖層檔齊全，但任何路徑走到這兩個編號都會讓遊戲結束。兩張地圖的內容見 [`cut_content/story.md`](../cut_content/story.md)。
- `ATTR151.DAT` 是孤兒：`DSC15.DAT` 只宣告一層，也沒有 `M151.MPL`／`M151.CEL`。另一個孤兒 `M09.CEL` 見 [`cel.md`](cel.md)。兩個孤兒檔的內容見 [`cut_content/story.md`](../cut_content/story.md)。

戰場上的判定（移動、地形修正、部署、搜尋、格子事件）只看**第 0 層**與事件碼層；第 1 層只參與繪圖。

## 一格的讀法

`fdps_map_load_tile_info(x, y)`（`0002ba00`，`src/maptile.c`）是各種判定讀一格的入口（移動範圍的 flood fill 另有一段自己讀圖磚編號的程式，但讀出的值沒有被用到，實際的移動消耗仍取自這支），它把一格的資訊存進 `0x69d04`..`0x69d0c` 的一組全域變數：

1. **圖磚編號**：第 0 層 `MPL` 在 `+0x0b + 2 × (y × W + x)` 的帶號 16-bit 值，`W` 是 `MPL` 自己的寬。
2. **屬性**：第 0 層 `ATTR` 在 `+0x11 + 4 × 圖磚編號` 的 4 byte——旗標、半透明程度、地形類別、戰鬥背景。
3. **事件碼**：`DTL` 在 `+0x10 + y × Wd + x` 的 byte，`Wd` 是 **`DTL` 自己的寬**，零延伸。
4. 移動網格的標記 byte，以 `MPL` 的寬索引（網格就是依第 0 層的尺寸配置的）。

**事件碼層與地形層的寬度在每一張地圖上都不同。** `DTL` 寬 27–64（多數是 64），`MPL` 寬 13–33；整張地圖的可用範圍是 `MPL` 的格子，`DTL` 裡所有非 0 的事件碼都落在左上角與 `MPL` 同大的矩形內。拿地形層的寬去索引事件碼層，讀到的是別格的事件碼。

## `MPL`：圖磚編號表

| 偏移 | 型別 | 內容 | 程式讀不讀 |
| ---: | --- | --- | --- |
| `0x00` | `char[4]` | `"MPL\0"` | 不讀 |
| `0x04` | `u8` | 版本，恆為 1 | 不讀 |
| `0x05` | `u16` | 編號表位置，恆為 `0x0b` | 不讀，程式寫死 `+0x0b` |
| `0x07` | `i16` | 寬（格數） | `MOVSX` |
| `0x09` | `i16` | 高 | `MOVSX` |
| `0x0b` | `i16[寬 × 高]` | 逐列的圖磚編號，即該層 `CEL` 的 sprite 索引 | `MOVSX` |

68 個檔的大小都剛好是 `11 + 2 × 寬 × 高`，所有編號都在 0 與該層 `CEL` 的 sprite 數之間。

執行中有兩個寫入者會改第 0 層的編號：重繪（編號 +1，見 [`map.md`](map.md) 的重繪格）、過場腳本的「設定格子」指令（`src/icon.c`，直接寫一個 16-bit 值）。另有一支 AI 函式把 `+0` 與 `+2` 當成寬高讀，讀到的是 magic，見 `src/aiact.h`。

## `DTL`：事件碼層

| 偏移 | 型別 | 內容 | 程式讀不讀 |
| ---: | --- | --- | --- |
| `0x00` | `char[4]` | `"DTL\0"` | 不讀 |
| `0x04` | `u8` | 版本，恆為 1 | 不讀 |
| `0x05` | `u16` | 恆為 14 | 不讀 |
| `0x07` | `i16` | 寬 | `MOVSX`，索引用 |
| `0x09` | `i16` | 高 | 不讀 |
| `0x0b` | `u8` | 平面數，恆為 1（`M31.DTL` 為 2） | 不讀 |
| `0x0c` | `u8[4]` | 恆為 `01 00 FF 00`（`M31.DTL` 為 `01 00 FF FF`） | 不讀 |
| `0x10` | `u8[寬 × 高]` | 逐列的事件碼 | 零延伸 |

檔案大小剛好是 `16 + 寬 × 高`，唯一例外是 `M31.DTL`：它宣告兩個平面，後面接著第二個平面再多 1 byte，程式只讀第一個。

出貨資料的事件碼是 0–15。0 在一般格上表示「無」，在寶箱與埋藏格上則是有效的記錄索引。同一個事件碼按該格的屬性類別有三種用法（查可搜尋格記錄、當重繪旗標、查格子事件），見 [`map.md`](map.md)。

## `ATTR`：圖磚屬性表

17 byte 的檔頭後面，每個圖磚編號一列 4 byte。檔頭在 69 個檔裡除了列數之外完全相同，程式一個欄位也不讀，列的位置寫死 `+0x11`：

| 偏移 | 型別 | 內容 |
| ---: | --- | --- |
| `0x00` | `char[4]` | `"ATR\0"` |
| `0x04` | `u8` | 版本 1 |
| `0x05` | `u16` | 恆為 `0x0d` |
| `0x07` | `u16` | 列數，等於該層 `CEL` 的 sprite 數（例外：`ATTR630.DAT` 288 列，`M630.CEL` 只有 192 個 sprite，多出的列用不到） |
| `0x09` | `u16[2]` | 恆為 4、4 |
| `0x0d` | `u8[4]` | 恆為 `01 01 01 01` |

每一列：

| 偏移 | 欄位 | 讀取者與語意 |
| ---: | --- | --- |
| `+0` | 旗標 | 見下 |
| `+1` | 半透明程度 | 旗標 `0x80` 的圖磚以這個值半透明繪製（`src/mapdraw.c`）；存進 `0x69d0a` 的那一份從來沒人讀。出貨資料全為 0 |
| `+2` | 地形類別 | 見下 |
| `+3` | 戰鬥背景 | 大於 0 就減 1，取 `BACKGRND.VFS` 的 `Back%02d.saf`（`src/combat.c`、`src/cmbspell.c`）；0 與 1 同樣取 `Back00`。出貨資料用到 0–63，對到 `BACK00`–`BACK62` |

### 旗標

| 位元 | 意義 | 讀取者 |
| --- | --- | --- |
| `0x07` | 動畫種類：1 是兩格交替（編號加上每 4 tick 翻轉一次的相位），2 是四格循環（編號加上 `((tick >> 2) & 3) × 0x60`），其他值不動 | `fdps_draw_scene_layer` |
| `0x60` | 屬性類別，是四值列舉不是兩個獨立位元：`0x00` 一般、`0x20` 寶箱、`0x40` 埋藏、`0x60` 重繪格。各類別怎麼被讀見 [`map.md`](map.md) | 搜尋、AI 搶寶箱、重繪、格子事件 |
| `0x80` | 半透明繪製 | `fdps_draw_scene_layer` |

動畫與半透明只在該層的屬性模式（`DSC`）非 0 時生效。出貨資料只出現 `0x00`、`0x02`、`0x20`、`0x40`、`0x42`、`0x60` 六種值：沒有兩格動畫、沒有半透明；四格動畫的圖磚在 `M210`、`M220`、`M230`、`M250`、`M320`、`M360`、`M410`、`M460`、`M510`、`M520`、`M530` 出現，四格都在圖磚表範圍內。

繪製時旗標取自**未加動畫偏移**的那一列，半透明程度取自**加了偏移**的那一列（`src/mapdraw.c` 的註解）。

### 地形類別

地形類別同時是三張表的索引：

| 類別 | 攻擊修正 | 防禦修正 | 可部署 | 第 0 層的格數 |
| ---: | ---: | ---: | --- | ---: |
| 0 | +5% | 0 | 是 | 21,988 |
| 1 | 0 | 0 | 是 | 161 |
| 2 | −5% | +10% | 是 | 1,018 |
| 3 | −5% | +10% | 是 | 0 |
| 4 | −5% | −5% | 是 | 0 |
| 5 | 0 | 0 | 否 | 7,028 |
| 6 | 0（越界讀取） | 0（越界讀取） | 否 | 3,222 |

- **攻防修正**是 `0x60040`／`0x60058` 兩張各 6 筆的表，`stat += 表[類別] × stat / 100`，飛行單位不套用。類別 6 讀到表外一格，原版靠資料段相鄰讀到 0，見 [`rebuild_info/pitfalls.md`](../rebuild_info/pitfalls.md)。
- **移動消耗**是 `PROMAP.DAT` 每個職業的 `move_cost[類別]`（[`assets/classes.md`](../assets/classes.md)），類別 6 在 40 個職業全是 `FF`（不可通行）。
- **可部署**：`fdps_deploy_unit` 找最近空格時只收類別小於 5 的格（`src/deploy.c`）。

攻略站把「草地」寫成 AP−5、DP+10，與類別 2 的修正相符。其他類別的名稱沒有可靠來源，本檔只用數字稱呼。

## `DSC`：圖層描述

`i32` 圖層數，接著每層 `0x20` byte：

| 偏移 | 型別 | 內容 |
| ---: | --- | --- |
| `0x00` | `i32` | x 捲動累加器初值 |
| `0x04` | `i32` | y 捲動累加器初值 |
| `0x08` | `i32` | x 視差係數（8 = 與視窗同步） |
| `0x0c` | `i32` | y 視差係數 |
| `0x10` | `i32` | 每 tick 的 x 捲動量 |
| `0x14` | `i32` | 每 tick 的 y 捲動量 |
| `0x18` | `u8` | 繪製深度 |
| `0x19` | `u8[3]` | 恆為 0，不讀 |
| `0x1c` | `u8` | 屬性模式 |
| `0x1d` | `u8[3]` | 恆為 0，不讀 |

圖層數不與 6 個 slot 比較，出貨檔是 1 或 2 層。繪製規則（`fdps_draw_scene_layers`、`fdps_draw_scene_layer`，`src/mapdraw.c`）：

- 各層依深度（無號）穩定排序；深度小於 10 的在單位之前畫、大於 10 的在單位之後畫，**等於 10 的永遠不畫**。
- 每層的原點是 `(視窗原點 × 視差係數 + 累加器) >> 3`，累加器每個 timer tick 各加一次捲動量；格座標以該層自己的寬高取餘數環繞。
- 屬性模式 0：整層直接畫，不看 `ATTR` 也不看移動網格。非 0：套用動畫；旗標 `0x80` 的圖磚以它的半透明程度與底下已畫的內容混色；其餘圖磚落在移動範圍內（網格標記不是 `0xff`）時隨脈動相位變色——模式 1 是朝色調色染色，其他非 0 值是與底下的內容混色。

出貨的組合只有四種：

| 地圖 | 層 | 視差 | 深度 | 模式 | 用途 |
| --- | ---: | --- | ---: | ---: | --- |
| 全部 | 0 | 8, 8 | 9 | 1 | 戰場本身 |
| 05、63 | 1 | 4, 2 | 8 | 0 | 第 0 層後方、慢速捲動的遠景 |
| 29 | 1 | 8, 4 | 8 | 0 | 同上，只有 y 方向慢速 |
| 07 | 1 | 8, 8 | 11 | 2 | 畫在單位**上方**的前景（牢籠柵欄） |

地圖 07 的前景層是 64×64，而移動網格照第 0 層配置成 33×25：繪製器用同一個格偏移同時索引圖層與移動網格，所以這一層在顯示移動範圍時讀到的標記 byte 是錯位的、而且會讀過網格區塊的尾端。

# VFS 容器格式

`.VFS` 是 FDPS 的具名檔案封裝容器。硬碟安裝後有 8 個，另有 2 個包在 `MISC.VFS` 裡；光碟上的 `PACK.VFS` 也是同一格式，內容見 [`disc_images.md`](disc_images.md)。

容器不壓縮也不加密：成員位元組原樣連續排列，容器大小恰好等於 header 加 entry table 加全部成員大小。

## 佈局

header 35 byte，緊接 `entry_count` 筆 26 byte 的 entry，再緊接成員內容。

| 偏移 | 型別 | 內容 |
| ---: | --- | --- |
| `0x00` | `char[3]` | magic `"VFS"` |
| `0x03` | `u16` | 版本，恆為 1 |
| `0x05` | `u16` | entry table 的偏移，恆為 35 |
| `0x07` | `u32` | entry 筆數 |
| `0x0B` | `char[24]` | 簽章字串 `Dynasty Information Co.,`（無結尾 NUL） |

每筆 entry：

| 偏移 | 型別 | 內容 |
| ---: | --- | --- |
| `0x00` | `char[13]` | 成員名稱，8.3 格式，NUL 結尾且其後補 0 |
| `0x0D` | `u32` | 成員大小 |
| `0x11` | `u32` | 同一個成員大小，重複一次 |
| `0x15` | `u8` | 恆為 0 |
| `0x16` | `u32` | 成員起點，自容器開頭起算 |

## 程式端只讀其中一部分

`FDPS.LE` 開啟容器時（`0x39ab0`）只讀 `0x05` 的 table 偏移與 `0x07` 的筆數，然後把整張 entry table 一次讀進記憶體；取用成員時（`0x39bd0`）只讀 entry 的名稱、`0x0D` 的大小與 `0x16` 的偏移。magic、版本、簽章、`0x11` 的重複大小、`0x15` 的保留 byte 五者程式從不讀取，也就沒有任何格式檢查——餵一個非 VFS 檔進去不會被擋下。

兩個由此而來的實際限制：

- **成員數上限 255**。成員查找（`0x39990`）把 `0x07` 的筆數以 8-bit 讀入，第 256 筆以後根本走不到。實際最多的 `FIELD.VFS` 是 223 筆。
- **entry table 偏移上限 0x7FFF**。開啟時以帶號 16-bit 值 seek。

成員名稱的比對是**單向**正規化，不是不分大小寫：查找前先把傳入的名稱就地轉成大寫，entry 自己的名稱則原樣取用，兩者以逐 byte 的 `strcmp` 比對。所以執行檔內寫成 `Fight.vfs`、`Misc.vfs` 這種混合大小寫查得到，反過來 entry 名稱只要不是全大寫就永遠查不到。實際上 1,202 個成員名稱全部是大寫、全部符合嚴格的 8.3，用到的字元只有 `A`–`Z`、`0`–`9`、`-`、`.`。

轉大寫是就地改寫呼叫端的緩衝區，所以查找過後傳入的那個字串會保持大寫。重建時若把這裡寫成 `stricmp(entry, query)`，遇到非大寫的 entry 名稱行為就與原版不同。

## 自洽性

容器的每個欄位都能互相驗證，不需要外部資訊：

- 第一筆成員的偏移等於 `entry table 偏移 + 26 × entry_count`
- 每一筆的偏移等於前一筆的偏移加大小——成員之間沒有間隙也沒有對齊填充
- 末筆的偏移加大小恰好等於檔案大小
- `0x11` 的重複大小等於 `0x0D` 的大小

10 個容器（8 個最外層加 2 個巢狀）全部通過這四項。

解出來的成員另有一道與容器無關的旁證：12 個 `.WAV` 全部是完整的 RIFF，檔頭記的長度加 8 恰好等於解出的長度；5 個 `.PAL` 一律 768 byte（256 × 3）；97 個 `.CEL` 全部以 `CEL\x01` 開頭，525 個 `.SAF` 全部以 `SAF\x06` 開頭。

## 巢狀容器

`MISC.VFS` 內有兩個成員本身是 VFS 容器：`BASEANI.VFS`（3 個 `SAF`）與 `BASEWAV.VFS`（9 個 `WAV`）。兩者的格式與最外層完全相同，包括那 24 byte 簽章。除此之外沒有其他巢狀層。

## 內容清單

`.SAF` 是數量最大宗的資源類型，最外層 522 個；`.WAV` 只有 3 個在最外層，另外 9 個包在 `BASEWAV.VFS` 內。

| 容器 | entry 數 | 容器大小 | 副檔名分布 |
| --- | ---: | ---: | --- |
| `BACKGRND.VFS` | 63 | 1,421,083 | SAF 63 |
| `FIELD.VFS` | 223 | 249,545 | COD 63、DAT 93、FON 1、TXT 66 |
| `FIELD1.VFS` | 201 | 8,934,513 | CEL 69、DTL 64、MPL 68 |
| `FIELD2.VFS` | 131 | 112,350 | DAT 131 |
| `FIGACT.VFS` | 91 | 22,632,235 | SAF 91 |
| `FIGHT.VFS` | 140 | 15,136,893 | SAF 140 |
| `ICONANI.VFS` | 133 | 4,718,103 | DAT 66、SAF 67 |
| `MISC.VFS` | 208 | 27,398,923 | CEL 28、DAT 9、PAL 5、SAF 161、VFS 2、WAV 3 |
| `MISC.VFS!BASEANI.VFS` | 3 | 36,906 | SAF 3 |

最外層合計 1190 個 entry：CEL 97、COD 63、DAT 299、DTL 64、FON 1、MPL 68、PAL 5、SAF 522、TXT 66、VFS 2、WAV 3

# 章節地圖腳本：`MAPnn.DAT` 與 `MAPnn.COD`

`FIELD.VFS` 裡每張戰場各有一個 `MAPnn.DAT`（回合事件、格子事件、可搜尋格記錄與部署記錄）與一個 `MAPnn.COD`（部署座標）。容器本身見 [`vfs.md`](vfs.md)；同一張地圖的地形層與事件碼層（`DTL`／`MPL`／`ATTR`／`DSC`）見 [`terrain.md`](terrain.md)。

## 命名與載入

檔名的 `nn` 是地圖編號（0–29 與章節索引重合，見 [`CONTEXT.md`](../CONTEXT.md)），以 `map%02d.dat`／`map%02d.cod` 組名。`FIELD.VFS` 有 `MAP00`–`MAP64` 共 63 組（沒有 `MAP30` 與 `MAP33`）；章節流程以章節編號 0–`0x1D` 載入 `MAP00`–`MAP29`。其餘的是過場用地圖，由過場腳本的 `SWITCH_MAP` 把章節編號改成該值後重建地圖單位而載入；哪支腳本切到哪張、切換時一併換掉的文字區塊見 [`cutscene_script.md`](cutscene_script.md)。`MAP31` 與 `MAP49` 沒有任何腳本或章節編號會切過去。地圖 31 與 33 即使被切過去也載入不了（缺 `DSC`，程式結束），見 [`terrain.md`](terrain.md)。

`MAPnn.DAT` 載入後整塊常駐在 `data_fdps_tile_event_data_table_ptr`，由 `fdps_field_load_chapter_resources`（`src/rsrc.c`）每次進地圖時重載。執行中唯一改寫它的是搜尋時的「以物易物」（見下），戰鬥中存檔則整塊連同其後的記憶體一起存下，見 [`save.md`](save.md)。

## `MAPnn.DAT`

| 偏移 | 內容 |
| ---: | --- |
| `+0x00` | 恆為 0，不讀 |
| `+0x01` | 我方 slot 數（無號） |
| `+0x02` | 部署記錄筆數 N（無號） |
| `+0x03` | 16 筆 3 byte 的回合事件，見下 |
| `+0x33` | 16 筆 2 byte 的格子事件，以（事件碼 − 1）× 2 索引，見下 |
| `+0x53` | 16 筆 3 byte 的可搜尋格記錄，以事件碼 × 3 索引，見下 |
| `+0x83` | N 筆部署記錄，每筆 `0x1a` byte，見下 |

三張表都沒有筆數欄位，也沒有任何讀取端檢查索引上限；出貨資料的事件碼只到 15，所以讀取都落在表內。檔案大小剛好是 `0x83 + 0x1a × N`，唯一例外是 `MAP31.DAT`：N 寫 2，後面多出 286 byte，恰為 11 筆完整的部署記錄，程式不會讀到。最大的檔是 `0x83 + 0x1a × 80` = `0x8a3` byte。

### 回合事件（`+0x03`）

每筆是（回合、處理函式 slot、陣營階段）。`fdps_battle_run_turn_events`（`0002e0c0`，`src/btlturn.c`）在每個陣營階段開始時把 16 筆全部掃一遍，回合等於回合計數器、陣營階段等於當下階段的每一筆都觸發，依表內順序，不會提前結束。處理函式 slot 指的是全域 50 格的章節事件處理函式表（`0x601c4`，`src/chapter.h`），呼叫時傳的單位索引固定是 0。

陣營階段的值就是那個階段所屬陣營的代碼，觸發時機由 `fdps_battle_advance_turn` 的順序決定。第 N 回合的我方行動結束後：

| 值 | 觸發時機 | 當時的回合計數器 |
| ---: | --- | --- |
| 1 | NPC 階段開始前 | N |
| 0 | 敵方階段開始前（「敵方回合」字卡之後） | N |
| 2 | 下一個我方階段開始前（「我方回合」字卡之後） | N + 1 |

回合計數器在進章節時設為 1，而我方階段的事件只在計數器加 1 之後才掃，所以**（1, *, 2）永遠不會觸發**；回合 0 同樣到不了。未使用的筆填（`FF`, `FF`, `00`），要等計數器走到 255 才會比對成立（`MAP02.DAT` 另有一筆（`FF`, `00`, `00`）也是）。出貨資料的陣營階段只用到 0 與 2（2 只出現在 `MAP13`、`MAP18`、`MAP22`、`MAP23`）。

### 事件碼的三種用法

每一格的事件碼取自事件碼層（[`terrain.md`](terrain.md)），它指到哪一張表，由**同一格**圖磚屬性的 `0x60` 類別決定：

| 屬性類別 | 事件碼的用途 | 讀取者 |
| --- | --- | --- |
| `0x20` 寶箱 | 可搜尋格記錄的索引，也是觸發旗標的索引 | 玩家的搜尋、AI 搶寶箱、重繪 |
| `0x40` 埋藏 | 可搜尋格記錄的索引，也是觸發旗標的索引 | 玩家的搜尋 |
| `0x60` 重繪格 | 觸發旗標的索引 | 重繪 |
| `0x00` 一般 | 事件碼非 0 時，是格子事件表的索引 | 單位經過或停留 |

觸發旗標是 `0x640d8` 起 32 byte 的章節共用陣列，進章節時清零、隨存檔保存。寫入者有三類：搜尋與 AI 搶寶箱（寫 1）、過場腳本的觸發指令（寫任意值）、各章的事件處理函式（多半借用 `0x10`、`0x11` 這兩個沒有格子用到的元素當一次性旗標）。

**重繪**（`fdps_map_apply_triggered_cell_changes`，`src/maptile.c`）：每次有人寫旗標後都掃整張圖，把「類別 `0x20` 或 `0x60`、且旗標已設」的格的圖磚編號加 1、事件碼清成 0。出貨資料裡加 1 之後的圖磚一律是類別 `0x00`，所以一格只會重繪一次。**埋藏格不會被重繪**，找過之後外觀不變，只靠旗標擋住再次搜尋。重繪格就是這個機制的純顯示用途：柵門、橋這類「事件發生後換圖」的格子。

**同一個事件碼可以用在多格**，它們共用同一筆記錄與同一個旗標：任一格被搜到，其他格就再也搜不到，而且同碼的寶箱全部一起變成已開啟。事件碼 0 也是有效的記錄索引，出貨資料有 40 個可搜尋格用碼 0。攻略站寫「只能開一個」的那些寶物（第 19、22、24、26 章）就是這個機制；攻略站沒寫到的同碼格也一樣有效，例如第 1 章 (22,23) 的埋藏格與 (18,17) 的寶箱共用記錄 0，第 7 章五個柱下的埋藏格都是碼 0。

### 可搜尋格記錄（`+0x53`）

每筆是種類 byte 加一個帶號 16-bit 內容，以事件碼 × 3 索引，所以事件碼 0 對到 `+0x53`。

玩家從行動選單搜尋（`fdps_battle_search_cell_at_cursor`，`000184f0`，`src/btlact.c`）只接受類別 `0x20` 與 `0x40`、且旗標還沒設的格，先問「要打開寶箱嗎」（`0x20`，文字 `0x20a`）或「要調查嗎」（`0x40`，文字 `0x20b`），答是之後依種類：

| 種類 | 內容 | 玩家搜到時 |
| ---: | --- | --- |
| 0 | 物品編號 | 放進背包、設旗標、重繪。背包滿時可以拿一件換：換出去的物品寫回這筆記錄的內容，**旗標不設、不重繪**，這一格之後還能再搜，拿到的是剛才換出去的那件 |
| 1 | 金額（帶號） | 加進隊伍金錢、設旗標、重繪；金額 0 顯示「什麼都沒有」 |
| 2 以上 | 章節事件處理函式 slot | 等 200 ms 後以搜尋者的單位索引呼叫該 slot；旗標與圖磚都不動，由處理函式自己決定 |

出貨資料被格子引用到的記錄只有種類 0（111 筆）與 1（27 筆）：物品編號在 `00`–`E1` 之內（`ITEM.DAT` 有內容的範圍，[`assets/items.md`](../assets/items.md)），金額 500–8,000。沒有任何格引用的非空記錄列在下方統計表，程式讀不到它們；其中有種類 2 的（`MAP07` 碼 6、7，那兩格是重繪格）、超出 `ITEM.DAT` 的物品編號（`MAP28` 記錄 5 是 `11F`、`MAP51` 記錄 6 是 `111`）。

AI 行為 5（見下）的單位也讀這張表。

### 格子事件（`+0x33`）

事件碼 c（1–16）的一筆在 `+0x33 + 2 × (c − 1)`：byte 0 是章節事件處理函式 slot（`0xff` 為無），byte 1 是觸發時機。`fdps_map_set_pending_tile_event`（`0002e030`）在單位回報「我在這一格」時比對觸發時機：

| 觸發時機 | 何時回報 |
| ---: | --- |
| 0 | 單位移動中每走進一格（`src/walk.c`，我方與 AI 都是） |
| 1 | 單位結束行動時停在這一格：我方單位只在「移動過再結束」時回報，原地行動不回報；AI 在每種行為之後都回報，行為 8 除外 |

比對成立就把 slot 記成「待處理事件」，等這個單位的行動結束後，以該單位的索引呼叫一次（`src/btlturn.c`）。一次行動裡經過多個觸發格時，後回報的蓋掉先回報的，只有最後一個會執行。類別非 0 的格（寶箱、埋藏、重繪格）一律不回報。出貨資料的觸發時機只用 0 與 1。地圖 31 以後的 `MAP` 檔也帶著格子事件表與可搜尋格記錄，但那些地圖的事件碼層全是 0，程式讀不到：格子事件表除了 `MAP51`、`MAP56` 全為 `(FF, 00)` 之外，都與 `MAP00` 相同；可搜尋格記錄則不是 `MAP00` 的那份（藥草、藥草、1000 元），多數共用另一份（500 元、藥草、藥草、解毒劑），`MAP51`（12000 元起的一串物品）與 `MAP56`（全 0）各自不同。

### 部署記錄（`+0x83`）

讀取者是 `fdps_deploy_wave`／`fdps_deploy_unit`（`00023830`／`000232b0`，`src/deploy.c`）：

| 偏移 | 內容 |
| ---: | --- |
| `+0x00` | 陣營：0 敵方、1 NPC、2 我方 |
| `+0x01` | 角色編號（肖像編號）；`0x3C` 以上查 `ENEMYDAT.DAT` |
| `+0x02`、`+0x03` | 不讀（14 筆在 `+0x03` 是 `0x12`，其餘全 0） |
| `+0x04` | 等級 |
| `+0x05`、`+0x06` | 裝備 |
| `+0x07`..`+0x0c` | 攜帶物品 |
| `+0x0d`..`+0x10` | 法術遮罩 |
| `+0x11` | AI 行為，見下 |
| `+0x12`、`+0x13` | 目的地 x、y；行為 3 與 9 把 `+0x12` 當成要追的角色編號 |
| `+0x14` | 事件碼：行為 5 要搶的寶箱 |
| `+0x15` | 波次：`fdps_deploy_wave(地圖, 波次, …)` 只部署這個值相符的記錄；開場部署波次 0 並放在錨點上，其餘波次由章節事件部署 |
| `+0x16` | 死亡腳本 opcode，見下 |
| `+0x17` | 死亡腳本的帶號 16-bit 運算元 |
| `+0x19` | 法術遮罩第 5 byte |

陣營與角色編號是兩個獨立欄位：陣營 0 的單位不一定是肖像編號 `0x3C` 以上的敵兵（`MAP12.DAT` 第 20 筆是陣營 0、角色編號 `0D`）。重建時的後果見 [`rebuild_info/pitfalls.md`](../rebuild_info/pitfalls.md)。

### AI 行為（部署記錄 `+0x11`）

複製到單位記錄 `+0x34`。`fdps_map_actor_behavior_step`（`00010010`，`src/mapai.c`）只看低 4 bit；高 4 bit 別處另有用途。章節事件改行為時多半保留高 4 bit，例外是第 15 章的結束處理與行為 5 開箱後改成 7，兩者都整個 byte 覆寫。「最佳行動」是對攻擊、法術、道具三種搜尋的評分擇一執行（`fdps_map_actor_take_best_action`），分數未達 6 就不算行動。

| 值 | 行為 |
| ---: | --- |
| 0 | 最佳行動；否則走向路徑最近的對手；否則走向直線最近的對手；否則休息 |
| 1 | 最佳行動；否則走向路徑最近的對手；否則休息 |
| 2 | 最佳行動；否則原地休息（不追擊） |
| 3 | 最佳行動；否則追目的地 x 指定的角色編號，那個角色不在場時同行為 0 |
| 4 | 不打，走向目的地 |
| 5 | 搶寶箱：最佳行動；否則走向事件碼等於 `+0x14`、類別正好是 `0x20` 的寶箱（埋藏格不算）；旗標已設或找不到時同行為 0 的移動部分。走到寶箱上就依記錄開箱：種類 0 或 1 的內容複製成自己的死亡腳本（種類 0 另外把物品放進自己背包），設旗標、重繪，行為改成 7 |
| 6 | 什麼都不做 |
| 7 | 不打，走向目的地；到達時退場（肖像 `0x24`–`0x27` 先播中毒動畫） |
| 8 | 什麼都不做，而且跳過行動結束的處理（不回報格子事件、不標記已行動、不重畫） |
| 9 | 不打，先走向目的地 x 指定的角色；一步都走不動時才改做最佳行動、再依序試兩種移動，全失敗就休息。角色不在場時同行為 0 |
| 10 | 道具優先：道具評分達 6 就用；接著攻擊評分達 6 就攻擊，否則走向路徑最近的對手，走不動就休息 |
| 11 | 法術優先：同 10，道具換成法術；肖像 `0x3c`–`0x3e` 的單位先觸發第 30 章的不死復活 |
| 12–15 | 什麼都不做 |

高 4 bit 的讀取者：`0x40` 讓攻擊在兩種平手時勝出（`src/mapai.c`），`0x80` 讓補血道具的評分乘 3（`src/aiscore.c`）；另外行為值的最低位（1、3、5、7、9、11）讓補血法術的評分乘 2。出貨的部署記錄高 4 bit 全是 0，用到的行為值是 0（1,043 筆）、1（14）、2（500）、3（73）、5（5）、7（27）、8（8）、11（6）。行為 5 只出現在 `MAP10`、`MAP13`、`MAP16`、`MAP19`，每一筆指到的寶箱都存在。

### 死亡腳本（部署記錄 `+0x16`）

單位被打倒時，由收集函式把 HP ≤ 0、未退場、opcode 不是 `0xff` 的單位的（opcode、運算元）排成一串，交給 `fdps_run_death_scripts`（`0001d990`，`src/death.c`），擊殺者是參數：

| opcode | 行為 |
| ---: | --- |
| 0 | 物品：運算元是物品編號，放進擊殺者的背包；背包滿時可以拿一件換，不換就消失 |
| 1 | 金錢：運算元是金額，加進隊伍金錢 |
| 2 | 章節事件：以擊殺者的單位索引呼叫運算元指定的處理函式 slot |
| 3 | 在畫面上畫一行本章文字，運算元是文字編號；`0xff` 與 −1 不畫 |
| 4 | 同 3，之後判定過關（戰鬥結束碼 2） |
| 5 | 同 3，之後判定敗北（戰鬥結束碼 1） |
| 6 以上 | 同 3 |
| `0xff` | 無 |

opcode 0 與 1 要求擊殺者是存活的我方單位；不是的話**整串**剩下的腳本都不執行（包括後面的 4、5）。AI 以法術擊殺時走另一個收集函式，只收 2–5，物品與金錢不會掉。我方單位建立時死亡腳本一律是 `0xff`。出貨資料的用量：0（316 筆）、1（97）、2（20）、3（11）、4（1）、5（7）、`0xff`（1,224）。

## `MAPnn.COD`

| 偏移 | 型別 | 內容 |
| ---: | --- | --- |
| `0x00` | `char[4]` | `"COD\0"`，不讀 |
| `0x04` | `u8` | `0x01` 或 `0x10`，不讀 |
| `0x05` | `u16` | 恆為 9，不讀 |
| `0x07` | `u16` | 記錄數，不讀 |
| `0x09` | 每筆 6 byte | `u16` 角色編號（不讀）、帶號 16-bit x、y |

程式只讀每筆的 (x, y)，位置寫死 `+0x0b + 6 × 索引`。前 N 筆依序對應 N 筆部署記錄（角色編號欄與部署記錄的 `+0x01` 相同），其後是我方各 slot 的起始格；出貨的每個檔記錄數都剛好是 N + 我方 slot 數。所有錨點座標的絕對值都不超過 49。

## 地圖單位索引不是部署記錄索引

slot 0..我方 slot 數 − 1 是隊伍成員，其後依記錄順序接上波次 0 的記錄，之後的波次依部署先後附加。

## 可部署格永遠夠用

每一章的戰場上，可部署格（地形類別 < 5）都是該章所有部署記錄加我方 slot 總數的 2.3 倍以上：可部署格最少的是地圖 21（第 22 章），168 格對 55 筆部署記錄加 11 個我方 slot；比例最緊的是地圖 22（第 23 章），217 格對 80 筆加 11 個。因此 `fdps_deploy_unit` 找最近空格時一定找得到，「整張圖沒有可放的格子」這條路徑用出貨資料走不到。

## 每張地圖的統計

由 [`tools/map_decode/`](../tools/map_decode/_index.md) 的 `report` 從出貨資料產生。`地形` 是第 0 層 `MPL` 的格數，`事件碼層` 是 `DTL` 的尺寸；`寶箱`／`埋藏`／`重繪格` 是第 0 層各屬性類別的格數；`事件格` 是類別 `0x00` 而事件碼非 0 的格，括號內是其中格子事件有處理函式的；`寶物記錄` 是被寶箱或埋藏格引用的不同記錄數；`未引用的非空記錄` 是內容不是（0, 0）卻沒有任何可搜尋格引用的記錄索引；`回合事件` 是 16 筆中不是填充筆的筆數。波次分佈只是記錄的計數；波次 0 以外的記錄要由章節事件以該波次呼叫 `fdps_deploy_wave` 才會出場（波次 `FF` 要以 255 呼叫），哪些波次實際不會出場由各章的章節事件決定，不在本表。

# 章節地圖腳本：`MAPnn.DAT` 與 `MAPnn.COD`

`FIELD.VFS` 裡每張戰場各有一個 `MAPnn.DAT`（回合事件、格子事件與部署記錄）與一個 `MAPnn.COD`（部署座標）。容器本身見 [`vfs.md`](vfs.md)。

## 命名與載入

檔名的 `nn` 是 0 起算的章節索引，以 `map%02d.dat`／`map%02d.cod` 組名。`FIELD.VFS` 有 `MAP00`–`MAP64` 共 63 組（沒有 `MAP30` 與 `MAP33`）；章節流程以章節編號 0–`0x1D` 載入 `MAP00`–`MAP29`。其餘的是過場用地圖，由 `ICON%02d.DAT` 腳本的 `SWITCH_MAP` 把章節編號改成該值後重建地圖單位而載入（例：`ICON11` 的 `SWITCH_MAP 0x34` 載 `MAP52`，`ICON08` 載 `MAP55`）；`MAP31` 與 `MAP49` 沒有任何腳本或章節編號會切過去（`WIN05.DAT` 開頭就是 `SWITCH_MAP 0x2E` 切到 `MAP46`，`WIN29` 切到 `MAP63`、`GOODEND` 切到 `MAP64`）。

## `MAPnn.DAT`

| 偏移 | 內容 |
| ---: | --- |
| `+0x01` | 我方 slot 數 |
| `+0x02` | 部署記錄筆數 |
| `+0x03` | 16 筆 3 byte 的回合事件：回合、處理函式 slot、陣營 |
| `+0x33` | 兩 byte 的格子事件，以（格子事件碼 − 1）× 2 索引：處理函式 slot（`0xff` 為無）、觸發時機 |
| `+0x53` | 三 byte 的可搜尋格記錄，以格子事件碼 × 3 索引：byte 0 是種類，byte 1 起的 word 是內容 |
| `+0x83` | 部署記錄，每筆 `0x1a` byte，見下 |

部署記錄：

| 偏移 | 內容 |
| ---: | --- |
| `+0x00` | 陣營 |
| `+0x01` | 角色編號（肖像編號） |
| `+0x04` | 等級 |
| `+0x05`、`+0x06` | 裝備 |
| `+0x07`..`+0x0c` | 攜帶物品 |
| `+0x0d`..`+0x10` | 法術遮罩 |
| `+0x11` | AI 行為 |
| `+0x12`、`+0x13` | 目的地 |
| `+0x14` | 格子事件碼 |
| `+0x15` | 波次 |
| `+0x16` | 死亡腳本 opcode |
| `+0x17` | 帶號 16-bit 運算元 |
| `+0x19` | 法術遮罩高位 |

陣營與角色編號是兩個獨立欄位：陣營 0 的單位不一定是肖像編號 `0x3C` 以上的敵兵（`MAP12.DAT` 第 20 筆是陣營 0、角色編號 `0D`）。重建時的後果見 [`rebuild_info/pitfalls.md`](../rebuild_info/pitfalls.md)。

## `MAPnn.COD`

從 `+0x0b` 起每 6 byte 一組帶號 16-bit (x, y)。前 N 組對應 N 筆部署記錄，其後是我方各 slot 的起始格。所有 `MAPnn.COD` 錨點座標的絕對值都不超過 49。

## 地圖單位索引不是部署記錄索引

slot 0..我方 slot 數 − 1 是隊伍成員，其後依記錄順序接上波次 0 的記錄，之後的波次依部署先後附加。

## 可部署格永遠夠用

每一章的戰場上，可部署格（地形 < 5）都比該章所有可能同時在場的單位多兩倍以上：最緊的一章（ch21）有 168 格，對 55 筆部署紀錄加 11 個我方 slot。因此 `fdps_deploy_unit` 找最近空格時一定找得到，「整張圖沒有可放的格子」這條路徑用出貨資料走不到。

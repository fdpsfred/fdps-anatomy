# 不建決定論 golden 測試系統，整合驗證靠人工實機遊玩

驗證架構分三層：純機械計算的 function 走 unit test（測試碼放在獨立的 translation unit，生產原始碼零改動）；`hash_check` / `eqcheck` 作為 build 的自我回歸閘；其餘的整合驗證全部由開發者在 DOSBox-X 中實際遊玩完成，時機安排在所有程式碼完成之後。

不建置錄製、擷取、framebuffer 對拍那一整套決定論測試系統。

## Considered Options

前作 FD2 建了一套 `FD2_REPLAY` harness——虛擬時鐘、輸入注入、framebuffer 與全域狀態檢查點，全部包在 `#ifdef` 內。實際結果是涵蓋規模極小，沒有發揮預期的自動化測試效果，卻讓生產原始碼被測試用程式碼滲透。

也評估過一個不需改動生產碼的替代設計：用 DOSBox-X autotype 驅動原版與重建版、從同一份 save-state 出發消除不決定性、比對記憶體快照做差分測試。技術上可行，但要建立可用的測試集需要投入大量實際遊玩與錄製的時間，判斷代價高於效益。

## Consequences

前作記錄的八類「編譯全綠、單元測試全綠，但在真機上行為偏離」的 bug（暫存器 clobber、BSS 相鄰性、熱迴圈指令數、fixup 綁錯符號等）會集中在專案末期一次浮現，且沒有自動化手段輔助二分定位。

緩解方式是在 emit 階段就把這八類隱性契約列入每個 function 的逐項檢查清單，盡量在寫的當下擋掉，而不是留到最後。

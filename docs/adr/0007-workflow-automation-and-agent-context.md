# 逐項工作一律以全自動 workflow 執行，判定寫檔控 context

凡是需要逐一處理 function 或 data 符號的工作，一律由一支 workflow 腳本從頭跑到尾，中途不回來要人確認。腳本負責的不只是分派工作，還包括把結果落地、跑驗證閘、產出知識庫與 devlog。

[ADR-0002](0002-no-batch-processing-per-function.md) 規定「一次一個」，本 ADR 規定「這件事怎麼跑完而不需要人推著走」。兩者一起構成本專案所有逐項工作的骨架。

## Considered Options

**每處理一批就回報等確認。** 票 12 前半段實際這樣跑過：9 個 function 一批，回報、等回覆、再跑下一批。以 1,042 個 function 的規模推算，光是等待回合就會有上百次，工作節奏完全被人的回覆延遲支配。**這是被明確否決的做法。**

**agent 直接把完整判定回傳給 orchestrator。** 這是最直覺的寫法，但 context 會隨處理量線性成長：一份 function 判定含 plate comment 與證據約 2–4 KB，一百個就是三十萬字元，orchestrator 與後續每一段都得扛。走到 1,042 個必然爆掉。

**讓 agent 直接寫 Ghidra。** 省一段轉錄，但多個 agent 併發寫入同一個 Ghidra 資料庫的安全性未經驗證，而且判定會在沒有任何一道關卡的情況下直接落地。

## Decision

四條，缺一不可：

**一、判定寫檔，只回傳摘要。** agent 把完整結果——命名、plate comment、prototype、證據、未決問題——寫成一個檔案，回傳給腳本的只有約 200 byte 的摘要（識別碼、名稱、信心、下一步）。**這是 context 管理的核心手段**：無論處理 100 個還是 1,000 個項目，腳本與後續每一段的 context 都不隨之成長。需要總覽的階段（寫知識庫、統計）讀的是從判定檔產生的精簡索引，不是判定檔本身。

**二、agent 只讀不寫目標資料庫，落地集中在轉錄階段。** 判定階段的 agent 不對 Ghidra 或原始碼做任何寫入。落地由獨立的一段執行，它不做判斷，只把已經定案的判定無損放進去。這樣併發寫入的風險不存在，而且落地是一個範圍明確的序列動作。

**三、轉錄之後必須跑驗證閘，而且要能自我修復。** 每一輪落地後跑該工作對應的 gate（Ghidra 側是孤立程式碼 0 與 error bookmark 0；建置側是編譯連結零錯誤零新增警告）。gate 不過就在當輪修，修不掉就明確回報失敗，不得掩蓋。

**四、必須有回掃段。** 每個 agent 只看自己那一個項目，所以身分取決於鄰居的項目，在鄰居還沒被處理時必然無解。工作結束前要把所有低信心或留有未決問題的判定挑出來重讀一次，這次允許 agent 讀鄰居的**判定檔**當證據。引用別人已經下好的判斷不是替別人下判斷，「一個 agent 一個項目」沒有被打破。重讀後仍無解就照實留著——提示必須明講「第二次嘗試不是硬掰結論的理由」。

## Consequences

票 12 是這套做法的第一個完整實例，量測結果：106 個 agent、0 錯誤、三輪落地的 gate 全部乾淨、109 個項目定案，全程無人介入。單一 agent 的 context 用量穩定在 42–67k token，與處理總量無關。

回掃段的必要性是實測出來的，不是設計時想到的：第一次跑完留下一個低信心判定，而推翻它的證據早就躺在同一個資料夾的另一個檔案裡（`0x305a0` 的身分取決於它唯一的 callee `0x3d8b2`，後者晚一輪才被走到）。那次是人補的，之後才把回掃寫進腳本。

每支 workflow 的形狀依工作內容決定，不強求照抄票 12 的階段劃分。要照抄的是上面四條。判定檔的欄位、gate 的內容、要不要 BFS 推進，都該按該工作重新設計。

**emit 階段的序列限制不因本 ADR 解除。** [ADR-0002](0002-no-batch-processing-per-function.md) 要求 emit 時一次只有一個 function 在飛，因為 reviewer 依賴版本控制的暫存狀態檢視改動。上面四條同樣適用於 emit，只是併行度為 1；若要並行，必須先解決 reviewer 的檢視範圍問題（例如 worktree 隔離），那是該階段自己的決定。

代價是 workflow 腳本本身變成需要維護的資產，而且第一次跑之前無法完全預知形狀。實務上的做法是先手動跑一小批把坑踩出來，再把踩到的東西寫進腳本與提示——票 12 的兩個工具坑（`__watcall` 不能寫在 prototype 字串裡、標記 no-return 會產生孤立程式碼）都是這樣進到腳本裡的。
